지식 그래프 학습

텍스트에 숨어 있는 주체–관계–객체를 명시적 그래프로 꺼내고, 더 나아가 검색 색인 자체를 실시간으로 순회하는 시맨틱 지식 그래프(SKG)로 해석하는 장이다.

이 장의 한 문장
문서는 단순한 문자열 묶음이 아니라, 함께 등장하는 용어와 문맥이 만든 거대한 관계 그래프다.

명시적 지식 그래프는 관계를 저장하고, SKG는 색인 안의 관계를 질의 순간에 발견하고 순위를 매긴다.

Reading map

두 종류의 그래프를 구분하면 전체가 보인다

이 장은 처음에는 NLP로 사실을 추출해 명시적 지식 그래프를 만드는 법을 보여주고, 후반에는 역색인과 정방향 색인을 오가며 관계를 즉석에서 계산하는 시맨틱 지식 그래프로 전환한다.

명시적 지식 그래프

노드와 간선을 미리 저장한다. 관계 이름이 분명하고 직접 순회하기 좋지만, 구축·정제·동기화 비용이 든다.

시맨틱 지식 그래프 · SKG

색인된 문서 집합의 통계로 노드와 간선을 질의 시점에 물질화한다. 별도 모델링 없이 도메인 관계를 발견한다.

01추출

문장에서 주체·동사·객체와 상하위 개념을 꺼낸다.

02순회

질의 → 문서 → 용어로 색인을 양방향 이동한다.

03적용

관련 용어로 질의를 확장하고 추천과 관계 탐색에 쓴다.

LLM으로 가는 징검다리

책은 SKG를 작은 언어 모델로 설명한다. LLM처럼 일반 언어를 폭넓게 추론하지는 않지만, 현재 검색 색인 안에 실제로 존재하는 관계를 질의할 수 있어 도메인 특화 문맥 추론에 강하다.

5.1 · Working with knowledge graphs

노드는 엔터티, 간선은 관계다

노드(node, vertex)는 용어·사람·장소·사물·개념 같은 엔터티이고, 간선(edge)은 두 노드 사이의 관계다. 간선을 따라가면 개별 사실을 결합해 새로운 사실을 추론할 수 있다.

그림 5.1의 학회 예시

저자 4명 → 공동 연구 논문 → DSAA 2016 → Montreal → Quebec → Canada, 그리고 개최 시점 October 2016이 연결된다. 이 간선을 따라가면 “한 저자는 2016년 10월 캐나다 Montreal에 있었다”는 사실을 추론할 수 있다.

지식 그래프를 얻는 세 가지 방법

처음부터 구축

Neo4j, Apache TinkerPop, ArangoDB 같은 그래프 DB로 도메인 모델을 직접 만든다.

기존 그래프 연결

ConceptNet, DBpedia, LLM 등 이미 구축된 일반 지식을 가져온다.

콘텐츠에서 자동 생성

현재 보유한 문서에서 도메인 엔터티와 관계를 추출한다. 이 장의 주된 선택이다.

혼합도 가능

기존 지식으로 시작하되, 조직 특유의 용어와 관계를 덮어쓰거나 추가할 수 있다.

일반 지식 검색에는 기존 그래프가 좋은 출발점이지만, 도메인 검색에서는 고유한 엔터티와 전문 용어가 빠질 수 있다. 그래서 콘텐츠로부터의 자동 생성이 중요하다.

5.2 · Using our search engine as a knowledge graph

그래프를 위해 꼭 새 시스템이 필요한 것은 아니다

책의 기본 검색 엔진인 Apache Solr는 그래프 순회 기능과 패싯 기반 집계를 이미 제공한다. 외부 그래프 DB는 더 복잡한 순회 문법을 줄 수 있지만, 요청 조정·데이터 동기화·인프라 운영이라는 새로운 비용도 만든다.

외부 그래프 DB

정교한 그래프 질의에 유리하다. 대신 검색 엔진과 별도 저장소의 데이터 일관성 및 운영을 책임져야 한다.

검색 엔진 통합

검색과 그래프 순회를 같은 색인에서 수행한다. 특히 역색인을 이용한 SKG 연산은 검색 엔진 안에서 효과적이다.

이 장의 범위

그래프를 어떻게 학습하는지에 집중한다. 구문 추출, 오탈자 탐지, 동의어 확장, 질의 재작성까지 묶는 완전한 시맨틱 질의 파이프라인은 7장에서 다룬다.

5.3 · Automatically extracting knowledge graphs

텍스트에서 사실을 꺼내는 Open Information Extraction

수동 그래프는 전문가 지식과 지속적인 갱신이 필요하고, 관리자의 편향과 오류가 들어갈 수 있다. Open Information Extraction(Open IE)은 문장의 품사와 의존 관계를 분석해 콘텐츠에서 사실을 직접 추출한다.

5.3.2 · Hyponyms and hypernyms

Hearst 패턴으로 “A는 B의 일종”을 찾는다

하위어(hyponym)는 더 구체적인 개념, 상위어(hypernym)는 더 일반적인 개념이다. phillips head → screwdriver → tool에서 Phillips head는 screwdriver의 하위어이고, tool은 screwdriver의 상위어다.

phillips head구체적 하위어
is_a →
screwdriver중간 개념
is_a →
tool일반적 상위어

명시적 추출은 손실이 있는 변환이다

삼중항만 떼어 저장하면 그 사실이 나온 문장과 문서의 주변 문맥이 사라진다. SKG는 용어를 원래 문맥과 분리하지 않고, 색인 안에서 실시간으로 관계를 순회해 이 문제를 줄인다.

5.4 · Semantic knowledge graphs

SKG는 문서 대신 “관련 용어”를 검색한다

시맨틱 지식 그래프는 도메인 안의 어떤 관계든 실시간으로 순회하고 랭킹할 수 있는, 자동 생성된 압축 모델이다. 일반 검색이 질의와 관련된 문서를 순위화한다면, SKG는 질의와 관련된 용어를 순위화한다.

Advil을 문서가 아니라 관계로 검색하기

건강 포럼을 색인한 뒤 advil 노드에서 출발하면 motrin, aleve, ibuprofen 같은 진통제 관련 용어가 나온다. 고정 동의어 사전이 아니라, 현재 코퍼스의 공동 출현으로 만든 동적 관련어다.

질의 확장

정확한 문자열이 없어도 개념적으로 가까운 문서를 찾는다.

추천

문서를 대표하는 관련 용어로 비슷한 콘텐츠를 검색한다.

분류·중의성 해소

용어가 어느 문맥과 범주에서 사용되는지 실시간으로 비교한다.

이상 탐지·정제

보통의 분포와 어긋나는 용어나 데이터를 찾는다.

좋은 데이터셋은 문맥이 반복된다

두 용어가 여러 문서에서 함께 나타나야 관계의 강도를 안정적으로 추정할 수 있다. 주제별 대표 문서 하나가 있는 Wikipedia보다 질문·포럼·채용 공고·리뷰처럼 여러 사용자가 비슷한 주제를 반복해 쓰는 컬렉션이 SKG에 유리하다.

책은 채용 공고 데이터와 Stack Exchange의 health, scifi, devops, travel, cooking 포럼을 사용한다.

5.4.3 · Structure of an SKG

용어 → 문서 → 용어, 두 번 이동하면 간선이 생긴다

SKG의 노드와 간선은 따로 저장하지 않는다. 검색 엔진이 이미 가진 역색인(inverted index)과 정방향 색인(forward index)을 오가며 질의 시점에 만든다.

질의·용어skill:Java

임의 질의도 문서 집합으로 해석되므로 하나의 노드가 된다.

역색인 →
문서 집합doc 1, 3, 6

질의와 일치하는 문서들의 교집합이 관계의 근거다.

그림 5.4–5.5의 세 관점
  • 자료구조 관점: 용어는 문서 목록으로, 문서는 용어 목록으로 매핑된다.
  • 집합 관점: 두 용어가 나타나는 문서 집합의 교집합이 관계다.
  • 그래프 관점: 용어가 노드, 교집합이 있는 두 노드 사이가 간선이다.

5.4.4 · Edge weights

많이 같이 나오는 것보다 “기대보다 더 같이 나오는가”가 중요하다

단순 공동 출현 횟수만 보면 the, a 같은 흔한 단어가 무엇과도 강하게 연결된다. 분포 가설의 핵심은 두 단어가 같은 문맥에서 나타날 뿐 아니라, 무작위 단어와 비교했을 때 유난히 비슷한 분포를 가져야 한다는 점이다.

relatedness(x, fg, bg) = (|Dx ∩ Dfg| − |Dfg| · Px) / √(|Dfg| · Px · (1 − Px)) Px = |Dbg ∩ Dx| / |Dbg| · 책의 식을 HTML 표기로 옮김
  • D_x: 후보 용어 또는 질의 x와 일치하는 문서 집합
  • D_fg: 비교 기준이 되는 전경(foreground) 질의와 일치하는 문서 집합
  • D_bg: 전체 컬렉션 또는 무작위 표본 같은 배경(background) 집합
  • P_x: 배경의 임의 문서에서 x를 만날 확률
pain을 전경으로, 전체 문서를 배경으로

advil이 전체 문서에서 흔한 정도보다 pain 문서에서 훨씬 자주 나오면 양의 관련도를 얻는다. 흔한 불용어는 전경과 배경의 비율이 비슷해 0에 가까워진다.

−1.0에 가까움서로 다른 영역에 치우침
0.0에 가까움특별한 관계가 없음
+1.0에 가까움강한 양의 관련성

Solr에서는 패싯이 term → docs → term 순회를, RelatednessAgg가 이 관련도 계산을 담당한다. 책의 skg.traverse()는 긴 JSON Facet 요청을 감싸는 추상화이며, transform_request()로 실제 엔진 요청을 볼 수 있다.

5.4.5 · Query expansion

Vibranium이 무엇인지 몰라도, 코퍼스가 문맥을 알려준다

SKG는 입력 질의를 노드로 삼아 개념적으로 가까운 용어를 찾는다. 이를 가중치와 함께 원래 질의에 더하면 희소 어휘 확장(sparse lexical expansion)이 된다.

원래 질의에는 임의로 5배 부스트를 주고, 확장 용어는 관련도만큼 가중한다. 원래 단어가 결과 목록에 다시 포함되는 것은 정상이다. 실제 질의가 구나 복합 표현일 수도 있으므로, 사용자의 원 질의를 별도로 보존하는 편이 안전하다.

Listing 5.7 · 정밀도와 재현율에 따라 재작성한다

단순 확장

원어 또는 확장어 하나만 있어도 일치한다. 재현율이 가장 넓다.query + expansion · min_match: 1

정밀도↑ 재현율↓

전체 용어의 30% 이상 일치를 요구해 더 풍부한 개념 문맥을 가진 문서만 남긴다.query + expansion · min_match: 30%

상위 정밀도↑

원래 vibranium을 필수로 하고 확장어를 랭킹 신호로 쓴다. 원문 일치 문서는 유지된다.vibranium AND (expansion) · min_match: 2

재현율 소폭↑

원래 단어를 필수로 하지 않고 두 용어 일치를 요구한다. 개념적으로 비슷한 새 문서가 들어올 수 있다.query + expansion · min_match: 2

결과 동일·랭킹 개선

원래 질의로 문서 집합을 고정하고, 확장어는 부스트에만 넣는다.query: vibranium · query_boosts: expansion

핵심 설계 질문

확장어를 매칭 조건으로 쓸지, 랭킹 신호로만 쓸지가 정밀도–재현율 균형을 결정한다. 가능한 재작성은 무한히 많으므로, 검색 목표와 평가셋으로 선택해야 한다.

5.4.6 · Content-based recommendations

문서의 단어를 주제에 맞게 다시 채점하면 추천 질의가 된다

사용자 행동이 부족해 협업 필터링을 쓰기 어려울 때, SKG는 문서 내용만으로 도메인 문맥을 반영한 추천을 만든다. 문서 안의 여러 용어를 알려진 주제와 비교해, 관련도가 높은 것만 남겨 질의로 사용한다.

5.4.7 · Arbitrary relationships

관계를 질의로 표현할 수 있다면, 관계 자체도 노드가 된다

지금까지는 모든 간선을 is_related_to로 보았다. 그러나 SKG에서 노드는 결국 문서 집합이므로, 관계를 근사하는 질의도 중간 노드로 만들 수 있다.

jean grey시작 노드
→
in love with관계를 표현한 중간 노드
→
관련 인물 후보summers · cyclops · xavier …
Listing 5.11 · 관계 노드를 물질화하는 코드 
scifi_skg = get_skg(engine.get_collection("scifi"))

starting_node = "jean grey"
relationship = "in love with"
nodes_to_traverse = [
    {"field": "body", "values": [starting_node]},
    {"field": "body", "values": [relationship],
     "default_operator": "OR"},
    {"field": "body", "min_occurrences": 25, "limit": 10}
]

traversal = scifi_skg.traverse(*nodes_to_traverse)

mutant와 x도 함께 나오듯, 관계는 코퍼스의 통계적 상관관계다. 사람·장소·사물을 먼저 개체명으로 추출해 색인하면 단일 토큰 대신 Scott Summers, Charles Xavier 같은 깨끗한 결과를 얻을 수 있다.

또한 관계가 원문 코퍼스에 충분히 논의되어야 한다. 예시는 우연한 동시 출현을 줄이기 위해 min_occurrences: 25를 사용한다. 책은 거짓 양성을 줄이려면 최소 발생 횟수를 1보다 크게 두라고 권한다.

5.5 · Using knowledge graphs for semantic search

지식 그래프는 질의 해석과 랭킹을 연결한다

SKG는 임의 질의에서 문맥에 민감한 관련 용어를 찾고, 각 관계에 점수를 준다. 이 능력은 질의 확장뿐 아니라 실시간 분류, 키워드 해석, 다의어 구분, 추천과 랭킹 개선의 기반이 된다.

명시적 그래프는 Open IE로 얻은 사실을 구조화하고, SKG는 원문 색인에서 관계를 동적으로 발견한다. 이후 장에서는 이 둘에 오탈자·동의어·도메인 구를 더하고, 실제 들어오는 질의를 올바른 엔터티와 문맥에 연결한다.

Summary

5장의 핵심을 다시 연결하기

01

그래프의 기본: 노드는 도메인의 엔터티, 간선은 엔터티 사이의 관계다. 간선을 따라가면 흩어진 사실을 결합할 수 있다.

02

Open IE: 의존 구문과 개체 인식으로 텍스트를 주체–관계–객체 삼중항으로 바꾼다.

03

관계 품질: 임의 동사 관계는 노이즈가 많지만, Hearst 패턴으로 얻는 하위어–상위어 is_a 관계는 더 깨끗하다.

04

SKG: 역색인과 정방향 색인을 오가며 별도 데이터 모델링 없이 색인된 콘텐츠를 지식 그래프이자 작은 언어 모델로 사용한다.

05

가중치: 단순 공동 출현이 아니라 전경에서의 실제 출현이 배경 확률의 기대치보다 얼마나 큰지를 관련도로 측정한다.

06

질의 확장: Vibranium처럼 낯선 용어도 코퍼스에서 관련 문맥을 찾고, 정밀도·재현율 목표에 맞춰 매칭 조건이나 랭킹 부스트로 사용한다.

07

콘텐츠 추천: 문서 용어를 주제에 대한 관련도로 걸러 추천 질의를 만들면 사용자 신호가 없어도 문맥을 아는 추천이 가능하다.

08

한계: SKG는 통계적 상관관계를 사용하므로 노이즈가 있고, 관계가 코퍼스에 충분히 표현되어 있어야 한다. 개체 추출과 최소 발생 횟수로 품질을 높일 수 있다.
