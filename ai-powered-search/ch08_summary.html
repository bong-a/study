01 / THE IDEA

이 장이 바꾸려는 것은 검색의 순위

같은 ipad 검색이라면, 사람들이 실제로 선택했던 iPad를 위로 올린다.

문서에 검색어가 많이 등장한다고 사용자가 그 문서를 원하는 것은 아닙니다. 원문에서는 ipad 검색 상단에 어댑터와 케이블이 나타납니다. 같은 검색에서 과거에 많이 클릭된 상품에 가점을 주면, iPad 본체가 상단에 올라옵니다. 이것이 신호 부스팅(signals boosting)입니다.

기억해야 할 단위는 ‘검색어 × 문서’입니다. 전체 사이트에서 잘 팔리는 상품 순위를 만드는 것이 아니라, 특정 검색어에서 어떤 문서가 선택되었는지를 모읍니다. ipad와 tablet에 대한 같은 상품의 부스트는 서로 다를 수 있습니다.

가장 잘 작동하는 곳: 자주 검색되는 질의

전체 검색량의 큰 비중을 차지하는 인기 검색어를 헤드 질의(head query)라고 합니다. 행동 데이터가 많이 쌓이므로, 인기 문서를 추정할 근거도 풍부합니다. 신호가 적은 질의나 새 문서에서는 이 방식만으로 순위를 충분히 개선하기 어렵습니다.

02 / BASIC AGGREGATION

검색과 클릭을 연결해 한 표로 모으기

이벤트 로그에는 검색어와 클릭한 상품이 별도 행으로 들어 있습니다. query_id로 둘을 연결하면 “어떤 검색 때문에 이 클릭이 발생했는가?”를 알 수 있습니다.

가장 단순한 모델B(q, d) = 해당 검색어 q에서 문서 d가 클릭된 횟수

집계 결과는 query / doc / boost 세 값으로 저장합니다. 이후 같은 검색어가 들어오면 이 값을 가져와 해당 문서를 부스팅합니다. 부스트는 최종 관련성 점수의 한 요소이므로, 클릭 수가 큰 순서와 실제 검색 순서가 항상 같지는 않습니다.

Listing 8.1의 핵심 · 검색과 클릭을 조인하고 집계하기

원문의 LEFT JOIN 뒤에서 q.type을 필터링하므로, 이 핵심 예제는 같은 연결 의미를 JOIN으로 표현했습니다. 애플리케이션의 저장·검색 헬퍼는 생략했습니다.

SELECT q.target AS query, c.target AS doc, COUNT(*) AS boost
FROM signals c
JOIN signals q ON c.query_id = q.query_id
WHERE c.type = 'click' AND q.type = 'query'
GROUP BY q.target, c.target
ORDER BY boost DESC;

이 단순 모델에는 아직 질의 정규화, 사용자 중복 제거, 행동별 가중치, 시간 감쇠가 없습니다. 다음 네 단계가 각각 다른 종류의 잡음을 줄입니다.

같은 의도의 신호가 흩어지지 않도록

04 / SIGNAL SPAM

클릭 5,000번이 5,000명의 지지는 아니다

원문은 한 사용자가 star wars를 5,000번 검색하고, 매번 스타워즈 테마 휴지통을 클릭하는 상황을 만듭니다. 단순 집계 모델은 이를 인기 상승으로 받아들여 휴지통을 상단에 올립니다.

한 사용자의 반복 클릭5,000단순 모델에서는 모두 가점
→
사용자별 중복 제거 후1동일 질의·문서에 한 표

해결책은 (사용자, 정규화된 검색어, 문서)마다 한 번만 세는 것입니다. 클릭 횟수를 고유 사용자의 표 수로 바꾸는 셈입니다. 최신 시각을 남겨 두면 나중에 시간 감쇠도 적용할 수 있습니다.

Listing 8.5의 핵심 · 안쪽에서 중복 제거, 바깥에서 표 합산

원문을 바탕으로 핵심 구문만 정리한 학습용 코드입니다.

WITH unique_votes AS (
  SELECT c.user AS user_id, LOWER(q.target) AS query, c.target AS doc,
         MAX(c.signal_time) AS signal_time
  FROM signals c
  JOIN signals q ON c.query_id = q.query_id
  WHERE c.type = 'click' AND q.type = 'query'
  GROUP BY c.user, LOWER(q.target), c.target
)
SELECT query, doc, COUNT(*) AS boost
FROM unique_votes
GROUP BY query, doc;

05 / WEIGHTED SIGNALS

행동마다 의도의 강도가 다르다

클릭은 관심의 시작, 장바구니는 더 강한 관심, 구매는 비용을 지불한 선택입니다.

원문이 사용하는 세 가지 양의 신호
신호예시 가중치해석
click · 클릭1많이 모이지만 단순 탐색일 수도 있다.
add-to-cart · 장바구니 추가10구매 의향이 더 강한 행동이다.
purchase · 구매25실제 지불을 수반하며 상대적으로 조작하기 어렵다.
원문의 가중합B = 1 × 클릭 수 + 10 × 장바구니 수 + 25 × 구매 수
직접 계산해 보기

같은 행동 수라도 가중치가 점수를 바꿉니다

설명용 데이터: 상품 A는 클릭 100회, 상품 B는 클릭 20회·장바구니 4회·구매 2회입니다. 중복 제거와 시간 감쇠는 이 계산에서 생략합니다.

상품 A100100 × 1
상품 B11020 + 4 × 10 + 2 × 25

신호 부스트는 상품 B가 10점 높습니다.

이 숫자는 신호 부스트의 비교입니다. 기본 관련성 점수를 포함한 최종 검색 순위는 별도입니다.

1:10:25는 예시이며 모든 서비스의 정답은 아닙니다. 장바구니에 넣으면 대부분 결제하는 서비스라면 ‘장바구니 추가’가 독립적인 정보를 거의 더하지 않을 수 있습니다. 원문은 수동 튜닝 또는 이후 장의 Learning to Rank로 가중치를 조정할 수 있다고 설명합니다.

Listing 8.6의 핵심 · 행동별 점수를 합산하기

원문의 다단계 SUM을 CASE 가중합으로 축약했습니다. Listing 8.6 자체에는 사용자별 중복 제거와 시간 감쇠가 포함되지 않습니다.

SELECT LOWER(q.target) AS query, s.target AS doc,
       SUM(CASE s.type
             WHEN 'click' THEN 1
             WHEN 'add-to-cart' THEN 10
             WHEN 'purchase' THEN 25
             ELSE 0
           END) AS boost
FROM signals s
JOIN signals q ON s.query_id = q.query_id
WHERE q.type = 'query' AND s.type <> 'query'
GROUP BY LOWER(q.target), s.target;

06 / TIME & HALF-LIFE

오래된 행동을 얼마나 오래 믿을까?

‘문서가 얼마나 오래 존재하는가’와 ‘행동 신호가 얼마나 빨리 낡는가’는 다른 질문입니다. 문서 수명이 짧다고 항상 과거 신호의 가중치를 낮춰야 하는 것은 아닙니다.

세 가지 서비스의 시간 전략
서비스문서와 신호의 성격집계 전략
RetroTech · 오래된 상품문서가 오래 유지되고, 새 행동이 더 중요하다고 보기 어렵다.적절한 수개월·수년 범위에서 동일 가중치. 변화가 느리면 잦은 재집계가 불필요하다.
채용 검색채용 공고는 짧게 존재하지만, 유효한 기간의 지원·클릭은 비슷한 가치를 가질 수 있다.신호는 빠르게 반영하되 시간별 동일 가중치도 가능. 문서가 사라지기 전 데이터가 부족할 수 있다.
뉴스 검색기사는 남아 있어도 현재 관심은 빠르게 바뀐다.최근 신호를 더 높게 평가하고, 신호 처리·모델 갱신도 빠르게 한다.

문서가 사라지기 전에 충분한 신호가 모이지 않는다면, 원문은 협업 필터링이나 Learning to Rank도 고려하라고 제안합니다. 신호가 쌓이는 속도와 문서 수명을 함께 봐야 합니다.

네 가지 개선을 하나의 집계로 연결하기

여기서는 앞 절의 아이디어를 합쳐 봅니다. 아래는 원문의 한 Listing을 그대로 옮긴 것이 아니라, 여러 절을 연결한 설명용 모델입니다. 음의 신호는 제외하고 클릭·장바구니·구매만 사용합니다.

학습용 통합 SQL · 정규화 + 유형별 중복 제거 + 가중치 + 30일 반감기

원문의 Spark SQL 계열 구문을 바탕으로 재구성했습니다. 저장된 signal_time을 날짜·시간으로 해석할 수 있다는 전제이며, 실제 엔진별 타입 처리는 확인해야 합니다. 이 HTML에서는 원본 데이터에 대해 실행하지 않았습니다.

WITH latest_signals AS (
  SELECT s.user AS user_id,
         LOWER(q.target) AS query,
         s.target AS doc,
         s.type AS signal_type,
         MAX(s.signal_time) AS signal_time
  FROM signals s
  JOIN signals q ON s.query_id = q.query_id
  WHERE q.type = 'query'
    AND s.type IN ('click', 'add-to-cart', 'purchase')
    AND s.signal_time <= '2024-06-01'
  GROUP BY s.user, LOWER(q.target), s.target, s.type
), weighted_signals AS (
  SELECT query, doc,
         CASE signal_type
           WHEN 'click' THEN 1.0
           WHEN 'add-to-cart' THEN 10.0
           WHEN 'purchase' THEN 25.0
         END AS type_weight,
         DATEDIFF('2024-06-01', signal_time) / 30.0 AS elapsed_halves
  FROM latest_signals
)
SELECT query, doc,
       SUM(type_weight * POW(0.5, elapsed_halves)) AS boost
FROM weighted_signals
GROUP BY query, doc;
중복 제거에 ‘행동 유형’을 추가한 이유

클릭과 구매처럼 의미가 다른 행동을 하나의 표로 합쳐 버리지 않기 위해서입니다. 이 정책은 유형별로 최신 한 건만 남기므로 반복 구매도 한 건으로 제한합니다. 반복 행동을 얼마나 인정할지는 서비스 정책으로 정해야 합니다.

통합 SQL의 '2024-06-01'은 예제의 기준 경계입니다. 해당 날짜 전체를 포함한다는 의미로 단정하지 말고, 실제 적용 시 날짜·시간 타입과 시간대를 명시해야 합니다.

원문 Listing 8.7은 출력 검색어를 LOWER(q.target)로 만들지만, 내부 GROUP BY에는 q.target을 사용합니다. 이 정리의 통합 SQL은 두 곳 모두 LOWER(q.target)로 통일하여 대소문자별 중복을 방지했습니다. 또한 DATEDIFF는 일 단위이므로 분·시간 단위 반응이 필요한 경우 시간 차이 계산도 그 단위에 맞춰야 합니다.

상위 N개 부스트만 가져오면 왜 페이지가 흔들릴까?

최종 점수에는 기본 관련성도 들어갑니다. 부스트가 작은 문서가 기본 점수는 높을 수 있으므로, 부스트 상위 10개가 최종 결과 상위 10개를 보장하지는 않습니다.

설명용 축소 예제 · 최종 점수 = 기본 점수 + 로드한 부스트라고 가정
문서기본 점수보유 부스트A의 부스트만 로드A·B 모두 로드
A10100110 · 1위110 · 2위
B10520105 · 2위125 · 1위

위 합산식은 현상을 보여 주기 위한 가정입니다. 책의 실제 엔진 점수식이나 원문 실측 데이터는 아닙니다.

첫 페이지에서는 A만 보여 줬는데, 다음 페이지에서 B의 부스트까지 로드하면 B가 앞 페이지로 올라가 사용자에게 누락될 수 있습니다. A는 다음 페이지로 밀려 중복 노출될 수 있습니다. 원문은 페이지마다 부스트를 10개 → 20개 → 30개로 늘리는 방식이 비용과 순서 일관성 문제를 함께 만든다고 설명합니다.

Index-time 방식은 이 ‘상위 N개만 적용’ 문제를 해결합니다. 그 자체로 모든 색인 변경이나 동시 갱신 상황에서 페이지 일관성을 보장한다는 뜻은 아닙니다.

색인 시점 부스팅의 모델을 교체할 때

예를 들어 클릭:구매 가중치를 1:25에서 1:20으로 바꾸면서 문서를 하나씩 덮어쓰면, 갱신 중 두 모델의 점수가 섞입니다. 원문은 새 필드를 채운 뒤 검색이 참조하는 필드를 바꾸는 방법을 제안합니다.

재색인량이 크면 CPU·메모리 사용이 검색 지연에도 영향을 줍니다. 원문은 색인 처리와 검색 제공을 분리하는 구조를 검토하라고 권합니다. 구체적인 복제·색인 분리 방식은 검색엔진 구현에 따라 달라집니다.

10 / REVIEW

다시 읽을 때는 이 여섯 가지를 확인

  1. 집계의 단위는 검색어 × 문서다.특정 검색에서 사람들이 선택한 결과를 다음 검색에 반영한다.
  2. 같은 검색어의 표현 변형을 먼저 합친다.정규화는 출력과 그룹 키에 같은 규칙으로 적용한다.
  3. 행동 횟수와 사람 수를 구분한다.사용자별 중복 제거로 한 사람의 반복 신호 영향력을 제한한다.
  4. 의도와 신뢰도가 다른 행동은 가중치를 다르게 준다.1:10:25는 시작 예시이며, 음의 신호도 고려할 수 있다.
  5. 시간 감쇠와 빠른 갱신은 별개의 선택이다.채용 공고처럼 감쇠 없이도 신속한 신호 반영이 필요한 경우가 있다.
  6. 검색 때 조회할지, 문서에 미리 색인할지 정한다.유연성·검색 비용·페이지 일관성·재색인 비용을 함께 비교한다.

스스로 설명해 보기

1. 소문자화만 하면 ipad 2와 ipad2도 합쳐질까?

아닙니다. 소문자화는 대소문자만 바꿉니다. 공백·형태 차이를 합치려면 별도 규칙이 필요하고, 의미 차이까지 지워 버리지 않도록 범위를 정해야 합니다.

2. 같은 사용자가 오늘 또 클릭하면 감쇠 모델은 그대로일까?

표 수는 여전히 하나지만, MAX(signal_time)을 남기는 방식이라면 대표 시각이 오늘로 갱신됩니다. 따라서 시간 감쇠 후 기여도는 커질 수 있습니다.

3. 반감기 30일일 때 60일 전 구매 한 건의 가치는?

기본 가중치가 25라면 25 × 0.5^(60/30) = 6.25입니다. 오늘 클릭 한 번의 가중치 1보다 큽니다.

4. 채용 문서는 수명이 짧으니 반드시 강한 감쇠가 필요할까?

원문의 가정에서는 아닙니다. 공고가 살아 있는 동안의 상호작용은 같은 가치를 가질 수 있습니다. 다만 짧은 수명 안에 신호를 활용해야 하므로 처리를 빠르게 해야 합니다.

5. 색인 시점 부스팅은 검색 시점의 점수 계산을 없앨까?

아닙니다. 문서에 검색어별 가중치를 저장해 두고, 검색 때 이를 읽어 관련성 점수에 반영합니다. 별도 부스트 조회와 긴 문서 ID 목록을 줄이는 방식입니다.
