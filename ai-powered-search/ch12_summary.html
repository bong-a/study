THE CENTRAL PROBLEM · pp.314–316

1. 클릭 로그에도 사각지대가 있다

dryer를 검색했는데 세탁기, 헤어드라이어, 건조기 전원 코드만 나온다고 생각해 봅시다. 사용자가 원한 것은 의류 건조기지만, 목록에 없으면 클릭할 수 없습니다. 이 클릭 로그로만 다시 학습하면 모델은 “사용자는 세탁기와 헤어드라이어를 좋아한다”고 배울 수 있습니다.

generate_training_data는 검색어·문서 쌍마다 clicked와 examined를 집계합니다. examined는 실제 시선 추적 결과가 아니라 클릭 모델이 사용자가 살펴봤다고 추정한 횟수입니다.

grade = clicked / examined
beta_grade = (clicked + w × p) / (examined + w)11장의 보정식을 다시 쓴 것입니다. w = prior_weight = 10, p = prior_grade = 0.2. 학습에는 관측 수를 고려한 beta_grade를 사용합니다.

예를 들어 blue ray의 문서 27242815414는 42번 살펴보고 42번 클릭했습니다. 단순 점수는 1.0이지만, 사전 보정을 하면 (42 + 2) / (42 + 10) = 0.846154입니다. 충분한 증거가 쌓이기 전에는 완벽하다고 단정하지 않습니다.

def a_b_test(query, model_a, model_b):
  draw = random.random()
  model_name = model_a if draw < 0.5 else model_b
  purchase_made = simulate_live_user_session(query, model_name)
  return (model_name, purchase_made)

def simulate_user_a_b_test(query, model_a, model_b, number_of_users=1000):
  purchases = {model_a: 0, model_b: 0}
  for _ in range(number_of_users):
    model_name, purchase_made = a_b_test(query, model_a, model_b)
    if purchase_made:
      purchases[model_name] += 1
  return purchases

results = simulate_user_a_b_test("transformers dvd",

1,000명과 구매 건수를 정확히 읽기

코드는 총 1,000회 반복하며 매번 50% 확률로 A 또는 B를 배정합니다. 각 모델에 1,000명씩이 아니며, 각 군이 정확히 500명인 것도 보장하지 않습니다. p.322의 설명보다 Listing 12.4의 실제 반복 구조를 기준으로 읽었습니다.

출력은 구매 건수입니다. 각 군의 실제 사용자 수와 통계 검정 결과가 없으므로 이 숫자만으로 정확한 전환율이나 통계적 유의성을 단정하지 않습니다.

구매를 바로 정답으로 쓰면 해결될까?

항상 그렇지는 않습니다. 클릭은 할인, 풍부한 설명, 상품 이미지 유무에도 영향을 받습니다. 구매는 상품 상세 페이지나 복잡한 결제 과정 때문에 줄어들 수도 있습니다. 장바구니·좋아요·즉시 뒤로 가기 같은 추가 신호는 유용하지만, 도메인에 맞게 해석해야 합니다.

책이 구분하는 지점은 실험군 전체의 성과 평가와 개별 검색어·문서의 관련성 판정입니다. 무작위 배정 후 다른 조건을 유지한 A/B 테스트는 랭킹 변화의 전체 효과를 비교할 수 있지만, 개별 상품은 구매가 드물고 다른 요인도 얽혀 있어 구매 여부만으로 관련성을 판정하기 어렵습니다.

가우시안 프로세스(Gaussian process, GP)는 예측을 하나의 숫자만으로 끝내지 않고 그 예측의 불확실성도 모델링합니다. 가까운 날짜의 강 수심이 비슷할 수 있듯, 비슷한 특성을 가진 검색 결과도 비슷한 관련성을 가질 수 있다는 가정을 활용합니다.

μ = predicted_grade · 예상 관련성
σ = predicted_stddev · 예측의 표준편차μ가 높으면 유망한 결과라고 예측합니다. σ가 크면 현재 모델의 예측이 불확실합니다. 불확실성이 크다는 사실 자체가 높은 관련성을 뜻하지는 않습니다.

탐색용 GP는 “어떤 유형을 더 알아볼까?”를 돕습니다. 기존 LTR은 “현재 지식으로 결과를 어떻게 정렬할까?”를 담당합니다. 이 장에서는 두 역할을 함께 사용합니다.

from sklearn.gaussian_process import GaussianProcessRegressor

def train_gpr(logged_judgments, feature_names):
  feature_data = logged_judgments[feature_names]
  grades = logged_judgments["grade"]
  gpr = GaussianProcessRegressor()
  gpr.fit(feature_data, grades)
  return gpr

상품부터 고르는 대신, 유형 16개부터 비교

특성 네 개가 각각 0 또는 1이면 가능한 조합은 2⁴ = 16개입니다. GP는 각 조합의 예상 관련성과 표준편차를 계산합니다. 이것은 아직 실제 상품 16개가 아니라, 탐색할 상품의 특성 조합 16개입니다.

def calculate_prediction_data(logged_judgments, feature_names):
  index = pandas.MultiIndex.from_product([[0, 1]] * 4,
                                         names=feature_names)
  with_prediction = pandas.DataFrame(index=index).reset_index()

  gpr = train_gpr(logged_judgments, feature_names)
  predictions_with_std = gpr.predict(
    with_prediction[feature_names], return_std=True)
  with_prediction["predicted_grade"] = predictions_with_std[0]
  with_prediction["predicted_stddev"] = predictions_with_std[1]

  return with_prediction.sort_values("predicted_stddev", ascending=True)

12.3.2 · EXPECTED IMPROVEMENT

6. 탐색 후보는 기대 개선량으로 고른다

EI가 낯설다면: 손계산과 그래프로 배우는 별도 설명 →

기대 개선량(Expected Improvement, EI)은 후보가 기준보다 좋아질 때, 그 개선 폭을 평균적으로 얼마나 기대할 수 있는지 계산합니다. 평균이 높아 유망한 경우도, 불확실성이 커서 더 좋은 결과일 가능성이 남은 경우도 고려합니다.

m = 현재 판정 grade의 평균
opportunity = μ − m − θ
z = opportunity / σ
EI = opportunity × Φ(z) + σ × φ(z)Φ는 표준정규분포 누적분포함수(CDF), φ는 확률밀도함수(PDF). 이 장의 기준은 최고 점수가 아니라 현재 grade의 평균 + θ입니다. σ > 0일 때의 식입니다.
  1. 기준 대비 여유를 계산: 예상 점수 μ에서 현재 평균 m과 탐색 조절값 θ를 뺍니다.
  2. 불확실성으로 확률을 계산: Φ(z)는 예측 분포가 기준 m + θ를 넘을 확률입니다.
  3. 개선의 크기와 가능성을 합산: 기준을 넘는 부분의 기대값인 EI가 큰 후보부터 탐색합니다.
Listing 12.8 · 기대 개선량으로 탐색 후보 점수 매기기
원문 기반 · 조판 정돈 · 원문 p.331
def calculate_expected_improvement(logged_judgments, feature_names, theta=0.6):
  data = calculate_prediction_data(logged_judgments, feature_names)
  data["opportunity"] = (data["predicted_grade"] -
    logged_judgments["grade"].mean() - theta)
  data["prob_of_improvement"] = (
    norm.cdf(data["opportunity"] / data["predicted_stddev"]))
  data["expected_improvement"] = (
    data["opportunity"] * data["prob_of_improvement"] +
    data["predicted_stddev"] *
    norm.pdf(data["opportunity"] / data["predicted_stddev"]))
  return data.sort_values("expected_improvement", ascending=False)

improvement_data = calculate_expected_improvement(
    logged_transformers_judgments, feature_names)
display(improvement_data)

opportunity가 음수인데 EI는 왜 양수일까?

평균 예측이 기준 아래여도, 예측 분포의 일부가 기준을 넘을 수 있습니다. EI는 그 양의 개선 부분을 평균한 값입니다. 따라서 원문 첫 후보의 opportunity가 −0.638497이어도 EI는 0.121201입니다. 수식의 첫 항은 음수가 될 수 있으므로 두 항을 각각 독립된 양수 ‘활용 점수’와 ‘탐색 점수’로 읽지 않습니다.

θ는 모르는 쪽으로 얼마나 나아갈지 조절한다

책은 기존 LTR을 보완할 탐색을 위해 theta=0.6을 사용합니다. θ를 높이면 기준이 올라가고 opportunity는 감소합니다. 이런 설정은 상대적으로 불확실성이 큰 후보를 선호하는 방향으로 작용할 수 있습니다. 다만 θ를 올린다고 EI 자체가 커지는 것은 아닙니다.

= 44 / 54 ≈ 0.814815단순 클릭 비율이 높아도 표본이 44회임을 고려해 보정합니다. 새 상품도 기존 상품과 같은 클릭 모델을 거칩니다.

원문 상품 정보에서 이 상품의 short_description과 long_description은 빈 문자열이며 has_promotion은 True입니다. 기존의 설명 필드 중심 접근만으로는 충분히 드러나지 않았던 가치를, 탐색으로 확인한 셈입니다.

12.4 · EXPLOIT, EXPLORE, GATHER, REPEAT

9. 스스로 배울 거리를 늘리는 LTR 루프

10~12장을 합치면, 검색 시스템은 사용자 행동을 받아 재학습할 뿐 아니라 다음 학습에 필요한 행동을 얻을 기회도 만듭니다. 책은 이 과정을 활용·탐색·수집 세 단계로 요약합니다.

  1. Exploit · 현재 지식으로 좋은 결과 제공기존 세션에서 판정을 만들고, 알려진 좋은 특성으로 주력 LTR 모델을 학습합니다.
  2. Explore · 학습 데이터 밖의 가설 검증새 탐색 특성을 정의하고 GP·EI로 유망한 후보 유형을 골라 일부 상품을 노출합니다.
  3. Gather · 노출과 반응을 함께 수집새 세션에서 클릭을 모으고 SDBN 판정을 다시 생성합니다. 원문 기본 재학습 주기는 하루입니다.
  4. Evaluate & repeat · 비교하고 다시 학습새 판정과 특성의 효과를 확인하고, 더 나은 탐색 모델을 주력 모델로 승격시키는 과정을 반복합니다.
Listing 12.14 · 활용 → 탐색 → 수집 → 재학습의 전체 루프
원문 기반 · 조판 정돈 · 원문 p.337
def train_and_deploy_model(sessions, model_name, feature_set):
  judgments = generate_training_data(sessions)
  train, test = split_training_data(judgments, 0.8)
  train_ranksvm_model(train, model_name, feature_set=feature_set)

def ltr_retraining_loop(latest_sessions, iterations=sys.maxsize,
                        retraining_frequency=60 * 60 * 24):
  exploit_feature_set = get_exploit_feature_set()
  train_and_deploy_model(latest_sessions,
                         "exploit",
                         exploit_feature_set)

  for i in range(0, iterations):
    judgments = generate_training_data(latest_sessions)
    train, test = split_training_data(judgments)
    if i > 0:
      previous_explore_model_name = f"explore_variant_{i-1}"
      exploit_model_evaluation = evaluate_model(test_data=test,
        model_name="exploit", training_data=train)
      explore_model_evaluation = evaluate_model(test_data=test,
        model_name=previous_explore_model_name, training_data=train)
      print(f"Exploit evaluation: {exploit_model_evaluation}")
      print(f"Explore evaluation: {explore_model_evaluation}")
      if is_improvement(explore_model_evaluation,
                        exploit_model_evaluation):
        print("Promoting previous explore model")
        train_and_deploy_model(latest_sessions,
                               "exploit",
                               explore_feature_set)

    explore_feature_set = get_latest_explore_feature_set()
    train_and_deploy_model(latest_sessions,
                           f"explore_variant_{i}",
                           explore_feature_set)

    wait_for_more_sessions(retraining_frequency)
    latest_sessions = gather_latest_sessions(
                        "transformers dvd",
                        latest_sessions,
                        explore_feature_set)

ltr_retraining_loop(sessions)

도우미 함수의 내부 구현 일부가 생략되어 있습니다. 모델 승격 조건은 evaluate_model과 is_improvement이며, 별도의 A/B 통계 검정이 이 코드에 완성되어 있는 것은 아닙니다. 본문에서 배운 온라인 검증의 필요성과 코드가 실제로 수행하는 일을 구분해서 읽으면 좋습니다.

자동화 이후에도 사람이 결정하는 것

이 예제의 탐색·활용 특성은 검색팀이 직접 고릅니다. 팀은 어떤 사각지대를 의심할지, 어떤 클릭 모델과 랭킹 모델을 쓸지, θ를 얼마나 둘지 결정합니다. 오래된 클릭 데이터를 정리하며 계절성과 트렌드에 따라 특성의 가치가 바뀌는지도 살펴봅니다.

책은 특성 생성 자체를 알고리즘이나 딥러닝으로 확장할 가능성도 언급합니다. 다만 이 장에서 구현한 것은 사람이 설계한 특성을 중심으로, 사용자에게서 배우는 범위를 지속적으로 넓히는 자동화입니다.

RECAP & SOURCE MAP

10. 다시 볼 때 기억할 다섯 문장

  1. 오프라인 점수가 좋다는 것은 기존 판정을 잘 맞춘다는 뜻이며, 실제 사용자 성과는 A/B 테스트로 확인합니다.
  2. 보이지 않은 상품에는 클릭도 없다. 클릭 모델을 정교하게 해도 노출 편향은 별도로 다뤄야 합니다.
  3. GP는 예상 점수 μ와 불확실성 σ를 함께 제공해 탐색할 유형을 고르는 데 도움을 줍니다.
  4. 이 장의 EI는 평균 grade + θ를 기준으로 개선 가능성을 계산합니다. 특성 조합을 고른 뒤 실제 상품으로 연결합니다.
  5. 탐색 → 클릭 수집 → 판정 재생성 → 재학습 → 재검증을 반복해야 새로운 지식이 주력 랭킹에 반영됩니다.

Judgment / grade · 판정 / 점수
특정 검색어에 대해 문서가 얼마나 관련 있는지를 나타내는 학습용 값.
SDBN · Simplified Dynamic Bayesian Network
사용자의 탐색·클릭 행동을 가정해 관련성을 추정하는 클릭 모델. 이 책에서는 베타 사전분포 보정도 사용합니다.
Presentation bias · 노출 편향
이전 모델이 보여준 결과에만 피드백이 쌓여 학습 범위가 제한되는 문제.
Exploit / explore · 활용 / 탐색
이미 배운 지식으로 좋은 결과를 제공하는 일과, 새 지식을 얻기 위해 결과를 시도하는 일.
Gaussian process · 가우시안 프로세스
특성에 대한 예측과 그 불확실성을 함께 모델링하는 방법.
Expected improvement · 기대 개선량
후보의 예측 분포에서 기준보다 나아지는 부분의 기대값. 이 장에서는 탐색 후보를 고르는 점수.
