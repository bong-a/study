01 / 원문 13.1–13.2

단어가 달라도, 의미는 가까울 수 있다

원문은 영어 “Hello to you!”와 아르메니아어 “Barev Dzes”로 시작합니다. 표기는 다르지만 둘 다 인사입니다. 임베딩(embedding)은 이런 의미와 문맥을 일정한 길이의 숫자 배열로 표현한 것입니다. 의미가 비슷한 텍스트가 가까워지도록 학습한 모델이라면, 글자가 겹치지 않는 두 표현도 연결할 수 있습니다. 원문 p.342

인사 예제는 두 언어를 같은 공간에 표현하도록 학습한 모델을 가정한 설명입니다. 뒤에서 사용하는 영어 RoBERTa 모델로 두 인사의 유사도를 측정한 결과는 아닙니다.

‘벡터’와 ‘차원’부터 풀어보기

벡터는 순서가 있는 숫자 목록입니다. [2, 5]에는 숫자가 두 개 있으므로 2차원 벡터라고 합니다. 지도에서 가로·세로 위치를 두 숫자로 나타내듯, 여러 특징을 숫자 칸에 담는다고 생각하면 됩니다.

문장 임베딩도 같은 형식입니다. 책의 768차원 임베딩은 문장 하나를 숫자 768개로 나타낸 것입니다. 768개 단어를 뜻하지 않습니다. 또 첫째 칸은 “날씨”, 둘째 칸은 “자동차”처럼 사람이 모든 칸의 뜻을 정해 둔 것도 아닙니다. 모델은 여러 숫자의 조합에 문맥을 담도록 학습합니다.

왜 문장을 굳이 숫자로 바꿀까?

컴퓨터는 숫자 목록끼리 얼마나 비슷한지 계산할 수 있습니다. “비가 온다”와 “밖이 젖었다”를 가까운 숫자 표현으로 바꾸면, 문자열이 같지 않아도 두 문장의 관계를 점수로 비교할 수 있습니다.

희소(sparse)는 많은 칸이 비어 있거나 0이라는 뜻입니다. 어휘별로 칸을 만들면 한 문서에 없는 단어의 칸은 대부분 0입니다. 밀집(dense)은 비교적 적은 고정된 칸에 정보를 나눠 담는 표현입니다. 대체로 많은 칸에 값이 들어 있지만, 모든 값이 반드시 0이 아니어야 하는 것은 아닙니다.

인덱스(index)는 빠르게 찾으려고 미리 정리한 자료구조입니다. 책 뒤의 찾아보기처럼, 단어마다 등장 문서를 모아 두면 역색인이 됩니다. BM25는 질의와 겹치는 단어가 문서에서 얼마나 중요하게 나타나는지 등을 이용해 점수를 매기는 대표적인 방식입니다.

그림 읽는 순서: 위쪽은 서비스가 미리 해 두는 일입니다. 문서를 인코더, 즉 텍스트를 벡터로 바꾸는 모델에 넣고 결과를 저장합니다. 아래쪽은 사용자가 검색할 때마다 하는 일입니다. 질의도 벡터로 바꾼 뒤, 저장한 문서 벡터와 비교합니다.

‘같은 의미 공간’은 같은 지도의 좌표 체계를 쓴다는 뜻에 가깝습니다. 서로 다른 지도의 숫자 좌표를 그대로 비교하면 엉뚱한 거리를 얻을 수 있습니다. 이 장에서는 문서와 질의에 같은 모델을 사용해 비교 기준을 맞춥니다.

문서 하나에 임베딩 하나면 충분할까?

긴 문서는 여러 주제를 섞어서 이야기합니다. 너무 큰 내용을 한 벡터에 담으면 세부가 흐려질 수 있고, 너무 짧게 자르면 문맥이 사라집니다. 그래서 문장·문단·의미 단위로 나누는 청킹(chunking)을 사용합니다. 원문은 경계를 넘는 문맥을 남기기 위해 청크를 겹치게 만드는 방법도 설명합니다. 원문 p.345

예를 들어 긴 야외활동 안내서에 매듭 묶기와 물 준비가 함께 실려 있다고 해 봅시다. “등반 매듭”을 검색할 때는 매듭 부분을 직접 찾는 편이 좋습니다. 그래서 부분별 벡터를 만들되, “이 방법은…”처럼 앞 문장을 가리키는 내용이 끊기지 않도록 경계를 정합니다. 이 안내서는 원문 개념을 설명하기 위한 보충 예입니다.

02 / 원문 13.2.2

같은 방향을 향할수록 비슷하다

벡터가 무엇을 나타내는지 정했다면, 이제 두 벡터가 얼마나 가까운지 계산합니다. 이 장은 주로 코사인 유사도를 사용합니다. 크기보다 방향이 얼마나 비슷한지를 보는 방법입니다.

2차원 벡터 [5, 3]을 원점에서 가로 5, 세로 3으로 뻗은 화살표로 그려 봅시다. 두 화살표 사이의 각도가 작을수록 코사인 값은 1에 가까워집니다. 같은 방향이면 1, 직각이면 0, 정반대 방향이면 −1입니다. 학습된 문장 벡터에서도 이 방향 관계를 유사도의 단서로 활용합니다.

차원 수와 벡터 길이는 다릅니다

차원 수는 숫자 칸의 개수입니다. 벡터 길이는 화살표의 크기입니다. [5, 3]은 2차원이고 길이는 약 5.831입니다. 따라서 “768차원 벡터의 길이를 1로 만든다”는 말은 칸 768개는 그대로 두고 숫자들의 크기를 조절한다는 뜻입니다.

cos(a, b) = (a · b) / (‖a‖ × ‖b‖)
길이를 1로 정규화하면 → cos(a, b) = â · b̂내적(dot product): 대응하는 차원의 값을 곱한 뒤 더합니다. 벡터의 길이: 각 값의 제곱을 더한 값의 제곱근입니다.

원문 숫자로 한 줄씩 계산하기

비교할 벡터는 b = [5, 3], c = [6, 2]입니다. 식의 ·는 내적, ‖b‖는 b의 길이, b̂는 길이를 1로 맞춘 b를 뜻합니다.

  1. 같은 칸끼리 곱해서 더합니다.
    b · c = 5×6 + 3×2 = 36
  2. 각 벡터의 길이를 구합니다.
    ‖b‖ = √(5²+3²) = √34, ‖c‖ = √(6²+2²) = √40
  3. 내적을 두 길이의 곱으로 나눕니다.
    36 ÷ (√34 × √40) ≈ 0.9762
    1에 가까우므로 두 화살표의 방향이 비슷합니다.

정규화는 각 숫자를 그 벡터의 길이로 나누는 것입니다. b는 [5/√34, 3/√34]가 됩니다. 방향은 유지되고 길이만 1이 되므로, 그다음 비교에서는 분모가 1×1이 됩니다.

계산해 보기 · 원문 그림 13.2의 벡터

a, b, c 중 어느 쌍이 가장 가까울까?

b ↔ c의 코사인 유사도: 0.9762

정규화하면 b = [0.8575, 0.5145], c = [0.9487, 0.3162]. 두 단위 벡터의 내적도 0.9762입니다.

원문 결과: cos(b,c)=0.9762 · cos(a,b)=0.7962 · cos(a,c)=0.6459. 화면의 값은 이 2차원 벡터로 직접 계산합니다. 실제 텍스트 임베딩을 2차원으로 모델링한 것은 아닙니다. 원문 p.345

정규화는 벡터의 방향을 유지한 채 길이만 1로 맞춥니다. 문서 벡터는 미리 한 번 정규화해 두고, 검색할 때 질의 벡터도 정규화하면 매번 벡터 길이로 나눌 필요 없이 내적만 계산할 수 있습니다. 원문의 예에서 [5, 3]과 [6, 2]의 코사인 값은 정규화 뒤 내적과 같습니다. 원문 p.347

그림에서는 끝점 사이의 직선거리보다 원점에서 뻗은 두 화살표 사이의 각도를 보세요. 차원이 수백 개로 늘어나도 계산은 같은 방식으로 대응하는 값들을 곱하고 더합니다.

점수는 관련성의 확률이 아니다

코사인 유사도의 수학적 범위는 −1~1입니다. 책의 일부 설명에 등장하는 0~1은 일반적인 범위가 아닙니다. 0.75가 “75% 확률로 정답”이라는 뜻도 아니며, 음수라는 이유만으로 반의어라고 단정할 수도 없습니다.

03 / 원문 13.3 · 13.4.2–13.4.3

문장을 읽고, 하나의 벡터를 남긴다

앞에서는 이미 벡터가 있다고 가정했습니다. 이제 그 숫자를 누가 만들어 주는지 살펴봅니다. Transformer(트랜스포머)는 문장 속 표현들의 관계를 학습하는 신경망 구조입니다. 그중 텍스트를 읽어 숫자 표현을 만드는 부분을 인코더라고 부릅니다. BERT와 RoBERTa는 이 계열의 언어 모델입니다.

원문은 빈칸 채우기 문제로 Transformer의 학습을 설명합니다. “I went to the ________ and bought some vegetables.”를 보면 store, market, grocer 같은 답이 떠오릅니다. 주변 문맥이 빈칸의 의미를 제한하기 때문입니다. BERT의 masked language modeling도 일부 토큰을 예측하도록 학습하는 방식입니다. 원문 p.349

한국어로는 “나는 ___에 가서 채소를 샀다”입니다. store는 가게, market은 시장, grocer는 식료품점을 떠올리게 합니다. 마스킹(masking)은 일부 입력을 가리는 일입니다. 원래 문장에서 단어를 가리면 그 원래 단어가 답이 되므로, 사람이 문장마다 정답을 새로 작성하지 않아도 학습 예제를 만들 수 있습니다.

이어지는 독해 예제는 강과 바다가 있는 지역을 묘사하고, 끝에서 그 장소가 교회 묘지임을 밝힙니다. “묘지는 바다에서 얼마나 멀리 떨어져 있는가?”에 답하려면 앞부분의 “twenty miles”, 즉 20마일이라는 정보를 연결해야 합니다. 어텐션(attention)은 각 토큰의 표현을 만들 때 다른 토큰의 정보를 서로 다른 비중으로 반영하는 연산입니다. 이 독해 문제는 멀리 있는 문맥도 연결해야 한다는 직관을 줍니다.

학습이 끝난 모델을 사용할 때 일어나는 일

토큰(token)은 모델이 읽는 단위입니다. 단어 하나일 수도 있고 단어의 일부일 수도 있습니다. 토큰으로 나누는 도구가 토크나이저(tokenizer)입니다. 모델은 각 토큰에 주변 문맥을 반영한 벡터를 만들고, 풀링(pooling)으로 토큰들의 벡터를 문장 하나의 벡터로 모읍니다.

→
문맥을 반영하기이미 학습된 인코더
→ 토큰별 표현
→
문장 표현으로 모으기Pooling · 값 모으기

그림 13.4와 SBERT 설명을 합친 개념 흐름입니다. 실제 토큰 분할은 모델의 tokenizer에 따라 달라집니다. 이 장의 목적은 문장을 생성하는 decoder가 아니라, 검색에 사용할 encoder의 표현을 얻는 것입니다.

예를 들어 평균 풀링은 첫째 차원의 값끼리 평균을 내고, 둘째 차원끼리도 평균을 내는 방식입니다. 토큰이 여러 개여도 결과는 같은 차원 수의 벡터 하나입니다. 다만 값들을 평균내는 연산만으로 좋은 의미 공간이 만들어지는 것은 아닙니다. 비슷한 문장을 가까이 놓도록 모델을 학습하는 과정이 함께 필요합니다.

토큰 벡터 [1, 3], [3, 5]
→ 각 칸의 평균 [(1+3)/2, (3+5)/2]
→ 문장 벡터 [2, 4]평균 풀링을 보여주는 보충용 숫자입니다. 원문 모델의 출력이 아닙니다. 토큰 2개를 하나로 모아도 벡터는 계속 2차원입니다.
학습·색인·검색은 서로 다른 시점입니다

학습: 데이터를 보면서 모델의 내부 숫자, 즉 가중치를 조정합니다. 색인: 학습된 모델로 문서 벡터를 만들어 저장합니다. 검색: 같은 모델로 질의 벡터를 만들고 저장된 벡터를 찾습니다. 아래 예제는 미리 학습된 모델을 불러와 사용하므로, 검색어를 입력할 때마다 모델을 다시 학습하지 않습니다.

def rank_similarities(phrases, similarities, name=None):
  a_phrases = []
  b_phrases = []
  scores = []
  for a in range(len(similarities) - 1):
    for b in range(a + 1, len(similarities)):
      a_phrases.append(phrases[a])
      b_phrases.append(phrases[b])
      scores.append(float(similarities[a][b]))

  dataframe = pandas.DataFrame({"score": scores, "phrase a": a_phrases,
                                "phrase b": b_phrases})
  dataframe["idx"] = dataframe.index
  dataframe = dataframe.reindex(columns=["idx", "score",
                                         "phrase a", "phrase b"])

  return dataframe.sort_values(by=["score"],
                               ascending=False,
                               ignore_index=True)

dataframe = rank_similarities(phrases, similarities)

전부 비교하면 얼마나 많은 계산이 필요할까?

전체 개념끼리 유사도를 살펴보는 분석에서는 n×n×d만큼 차원별 비교가 필요합니다. 여기서 n은 개념 수, d는 차원 수입니다. 원문은 먼저 250개만 골라 유사도 분포를 확인합니다.

마지막 행은 보충 계산입니다. 계산량이 입력 크기에 따라 얼마나 늘어나는지 적는 빅오(Big-O) 표기로는 각각 O(n²d)와 O(nd)입니다. 정확한 실행 시간을 뜻하는 표기는 아닙니다. 원문 p.363의 “exponentially”는 여기서는 지수 증가가 아니라 제곱 증가로 읽어야 합니다.

KNN은 질의에 가까운 k개를 찾는 문제입니다. ANN(approximate nearest neighbor)은 그 이웃을 근사적으로 빠르게 찾는 접근입니다. 약간의 누락 가능성을 받아들이는 대신, 대규모 데이터에서 모든 벡터를 비교하는 부담을 줄입니다. 원문 p.365

여기서 k는 가져올 후보 개수입니다. “가장 가까운 5개”를 찾고 싶으면 k=5입니다. 전수 검색은 저장한 벡터를 하나도 빠짐없이 비교합니다. ANN은 미리 만든 탐색 구조를 따라 유망한 후보를 찾으므로, 전수 검색의 상위 k개와 결과가 조금 다를 수 있습니다.

HNSW · 이웃을 따라 이동

가까운 벡터를 연결한 여러 층의 그래프를 만듭니다. 거친 층에서 유망한 영역으로 이동한 뒤 세밀한 층에서 이웃을 탐색하는 식으로 생각하면 쉽습니다.

IVF · 탐색할 구역을 제한

벡터를 여러 클러스터의 목록에 나눠 저장하고, 질의에 가까운 일부 목록만 살펴봅니다. 뒤의 조합 예제는 256개 클러스터 중 4개를 탐색합니다.

그래프는 점들과 그 사이의 연결로 된 구조입니다. HNSW에서는 벡터가 점, 이웃 관계가 연결입니다. 클러스터는 비슷한 벡터를 모은 무리입니다. IVF는 각 무리의 문서 목록 중 어디를 살펴볼지 고릅니다. “이웃 연결을 따라간다”와 “몇 개의 무리만 살펴본다”는 차이로 기억하면 됩니다.

원문에 잠깐 나오는 LSH는 무엇일까?

LSH는 비슷한 입력이 같은 바구니에 들어가기 쉽도록 만든 해시 함수를 이용하는 접근입니다. 해시는 입력을 번호 같은 값으로 바꾸는 규칙이고, 버킷은 같은 번호의 항목을 모은 바구니입니다. 원문은 HNSW 외의 대안으로 소개하며, 이 장의 자동완성 코드는 HNSW를 사용합니다.

NMSLIB 예제는 method="hnsw", space="negdotprod"로 인덱스를 만듭니다. 정규화한 벡터의 음의 내적을 거리로 사용하므로, 반환값에 −1을 곱해야 우리가 읽는 유사도가 됩니다.

유사도가 0.9이면 이 방식의 거리는 −0.9이고, 유사도 0.7이면 거리는 −0.7입니다. 거리에서는 더 작은 −0.9가 앞에 옵니다. 코드는 부호를 다시 뒤집어 화면에 0.9라는 유사도로 보여줍니다. “유사도는 클수록 가깝고, 거리는 작을수록 가깝다”는 기준을 맞춘 것입니다.

def embedding_search(index, query, phrases, k=20,
                     min_similarity=0.75):
  matches = []
  query_embedding = transformer.encode(query)
  query_embedding = normalize_embedding(query_embedding)
  ids, distances = index.knnQuery(query_embedding, k=k)
  for i in range(len(ids)):
    similarity = distances[i] * -1
    if similarity >= min_similarity:
      matches.append((phrases[ids[i]], similarity))
  if not len(matches):
    matches.append((phrases[ids[1]], distances[1] * -1))
  return matches
def semantic_suggest(prefix, phrases):
  matches = embedding_search(concepts_index, prefix, phrases)
  print_labels(prefix, matches)

① Scalar quantization · 숫자 한 칸의 정밀도를 낮춘다

각 차원의 실숫값을 더 적은 비트로 표현합니다. Float32 → Float16은 한 값당 4 bytes를 2 bytes로 줄이고, Int8은 1 byte로 줄입니다. Int8 방식은 값의 범위를 −128~127의 단계에 매핑합니다. 문서와 질의에 서로 다른 변환 기준을 쓰면 비교의 의미가 달라질 수 있습니다.

스칼라(scalar)는 여기서 숫자 한 개를 뜻합니다. 정밀도는 가까운 값의 작은 차이를 얼마나 세세하게 구별하는가입니다. Int8은 정수를 8비트로 저장하는 형식이며, 부호가 있는 Int8은 −128부터 127까지 256개 값을 구별합니다.

② Binary quantization · 차원마다 한 비트만 남긴다

각 차원을 0 또는 1로 표현합니다. 단순한 방식은 x > 0 → 1, 나머지는 0으로 매핑합니다. 원문은 특징별 임계값과 모델이 직접 학습한 이진 표현도 개념적으로 소개합니다. 보존되는 정보가 적어진 만큼, 후보를 넓게 가져와 원본 벡터로 재랭킹하는 단계가 중요해집니다.

설명용 원래 값: [−0.8, 0.2, 0.9, −0.1]
양수인지 여부만 남기면: [0, 1, 1, 0]보충 예제입니다. 0.2와 0.9의 차이는 사라지고, 둘 다 양수라는 사실만 남았습니다. 숫자 칸 4개는 그대로입니다.

이진 벡터는 서로 다른 비트의 자리 수로 비교할 수 있습니다. [0,1,1,0]과 [0,1,0,0]은 셋째 자리만 다르므로 거리가 1입니다. 이를 해밍 거리(Hamming distance)라고 하며, 작을수록 비슷합니다. 원문의 FAISS 이진 인덱스도 이 거리를 사용합니다. FAISS 공식 설명

③ Product Quantization · 벡터 조각을 대표 ID로 바꾼다

스칼라 양자화가 숫자 한 칸씩 줄인다면, PQ는 벡터를 여러 조각으로 나눠 각 조각을 대표 벡터의 ID로 대체합니다. 원문 그림에서는 네 부분의 중심 ID가 [41, 255, 37, 7]입니다.

원리를 먼저 풀면 이렇습니다. 비슷한 벡터 조각들을 한 무리로 묶고, 그 무리를 대표하는 중심 벡터(centroid)를 정합니다. 대표 벡터마다 번호를 붙인 대응표가 코드북(codebook)입니다. 문서마다 원래 숫자 조각을 저장하는 대신 “대표 조각 몇 번과 비슷하다”는 번호를 저장합니다.

위에서 아래로 읽으세요. 하나의 벡터를 네 조각으로 나누고, 각 조각에 가장 가까운 대표 벡터를 찾은 뒤 번호만 남깁니다. [41, 255, 37, 7]은 “첫 조각용 사전의 41번, 둘째 조각용 사전의 255번…”이라는 뜻입니다.

번호 자체는 유사도 점수가 아닙니다. 255번이 41번보다 더 좋다는 뜻도 아닙니다. 조각 위치마다 별도의 사전이 있습니다. 그림은 네 조각으로 원리를 보여주고, 아래 코드 실험은 16개 조각을 사용합니다.

  1. 1,024차원 벡터를 M=16개로 나눈다M은 조각 수입니다. 조각마다 숫자 칸은 1,024÷16=64개입니다. 모든 문서의 같은 위치 조각을 비교하는 공간을 부분 공간이라고 부릅니다.
  2. 조각 위치마다 대표 벡터 256개를 학습한다8비트는 2⁸=256가지 상태를 나타내므로, 256개 중 하나의 번호를 1바이트에 담을 수 있습니다. 대표 벡터들은 코드북에 저장합니다.
  3. 문서에는 조각별 가장 가까운 대표 번호를 저장한다문서 한 개의 PQ code는 16개 ID × 1 byte = 16 bytes입니다. 모든 문서가 함께 쓰는 코드북과 다른 부가정보는 별도입니다.
  4. 질의가 올 때 거리 조회표를 만들고, 문서별 값을 합한다새 질의의 각 조각과 대표 벡터들 사이의 거리를 먼저 계산합니다. 이 표가 lookup table입니다. 문서마다 저장된 대표 번호로 값을 찾아 더하므로, 원래의 64개 숫자를 매번 전부 비교할 필요가 줄어듭니다.

M을 16에서 64로 늘리면 문서마다 저장할 ID가 많아지지만, 더 세밀한 조각을 표현할 수 있습니다. 원문은 이 변경으로 재랭킹 후 recall이 0.6800 → 0.9911로 높아진 예를 보여줍니다. 비용과 품질 사이에서 고를 수 있는 손잡이입니다.

MRL은 학습 방식이다

아무 임베딩이나 뒤를 잘라도 의미를 보존할 수 있는 것은 아닙니다. MRL을 지원하도록 학습한 모델을 사용해야 합니다. 또한 정규화한 벡터를 자르면 길이가 더 이상 1이 아닐 수 있으므로, 잘라낸 벡터의 내적과 코사인을 동일시하면 안 됩니다.

양자화는 한 칸을 작게

[값₁, 값₂, 값₃, 값₄]
→ [작은값₁, 작은값₂, 작은값₃, 작은값₄]

스칼라·이진 양자화는 네 칸을 유지하면서 각 칸에 쓰는 비트를 줄입니다.

[값₁, 값₂, 값₃, 값₄]
→ [값₁, 값₂]

이 비유에서는 앞의 두 칸만 사용합니다. MRL 학습을 거친 벡터라야 유용한 의미를 남길 수 있습니다.

recall을 작은 목록으로 계산해 보기

재현율(recall)은 찾아야 할 대상 중 얼마나 찾았는지를 나타냅니다. 중요한 것은 “찾아야 할 대상”을 무엇으로 정했느냐입니다. 이 실험에서는 사람이 정한 정답 대신, 원래 벡터로 정밀 검색한 상위 결과를 기준으로 삼습니다.

정밀 검색의 상위 4개: [A, B, C, D]
압축 검색의 상위 4개: [A, C, X, Y]
공통 문서: A, C → 2 ÷ 4 = 0.5 = 50%recall@4의 뜻을 보여주는 보충 예입니다. A~Y는 문서의 임시 이름이며, 원문 실험 데이터가 아닙니다. @4는 상위 4개를 기준으로 삼았다는 표시입니다.

문서가 들어 있는지만 세는 이 기준에서는 결과가 [D,C,B,A]여도 100%입니다. 순서가 같은지와 그 문서가 사람에게 정말 유용한지는 별개의 질문입니다. 책의 정밀 검색을 100% 재현했다고 해서 완벽한 검색이라는 뜻은 아닙니다.

25개만 필요한데 왜 50개를 가져올까?

설명을 위해, 정밀 검색에서 10위인 문서 B가 압축 검색에서는 31위로 밀렸다고 가정해 봅시다. 25개만 가져오면 B가 후보에 없으므로 다시 정렬해도 등장할 수 없습니다.

압축 검색에서 31위25개만 가져오면 탈락
→
후보를 50개로 확대문서 B도 비교 대상에 포함
→
원래 벡터로 재정렬상위 25개에 다시 들 기회

반대로 B가 80위까지 밀렸다면 50개 후보에도 없습니다. 후보 확대는 놓친 문서를 가져올 기회를 늘리고, 재랭킹은 가져온 문서의 순서를 다듬습니다. 두 작업이 함께 있어야 하는 이유입니다.

표 읽는 법: ms는 1초의 1,000분의 1입니다. 검색 시간과 인덱스 크기는 작을수록 비용이 적습니다. Recall은 클수록 기준 문서를 많이 유지했습니다. 오른쪽 열은 후보를 늘려 정밀 재랭킹한 뒤의 일치율입니다. 한 행에서 이 값들을 함께 읽으세요.

def evaluate_rerank_search(full_index, optimized_index,
                           query_embeddings,
                           optimized_embeddings,
                           k=50, limit=25):
  results, full_results = evaluate_search(
                            full_index,
                            optimized_index, None,
                            query_embeddings,
                            optimized_embeddings,
                            display=False, k=k)

  doc_embeddings = get_outdoors_embeddings(model)
  rescore_scores, rescore_ids = [], []
  for i in range(len(results["results"])):
    embedding_ids = results["faiss_ids"][i]
    top_k_embeddings = [doc_embeddings[id]
                        for id in embedding_ids]
    query_embedding = query_embeddings[i]
    scores = query_embedding @ \
             numpy.array(top_k_embeddings).T
    indices = scores.argsort()[::-1][:limit]
    top_k_indices = embedding_ids[indices]
    top_k_scores = scores[indices]
    rescore_scores.append(top_k_scores)
    rescore_ids.append(top_k_indices)

  results = generate_search_results(rescore_scores, rescore_ids)
  recall = calculate_recall(full_results["results"], results)
  print(f"Reranked recall: {recall}")

def index_binary_ivf_mrl_embeddings(reduced_mrl_doc_embeddings,
                                    binary_index_name):

    reduced_mrl_doc_embeddings,
    calibration_embeddings=reduced_mrl_doc_embeddings,
    precision="binary").astype(numpy.uint8)

            quantizer, dimensions, num_clusters)
  index.nprobe = 4

  index.add(binary_embeddings)
  faiss.write_index_binary(index, binary_index_name)
  return index

따로 읽어 찾고, 함께 읽어 순위를 다듬는다

앞 절의 재랭킹은 압축 때문에 흐트러진 순서를 원래 벡터 검색에 가깝게 복구하는 작업이었습니다. 그런데 원래 벡터 검색의 1위가 사용자에게 가장 좋은 답이라는 보장은 없습니다. 이번에는 관련성을 판단하는 방법 자체를 더 세밀하게 바꾸는 재랭킹을 살펴봅니다.

지금까지는 질의와 문서를 각각 인코딩하고 두 벡터를 비교했습니다. 이 구조가 bi-encoder입니다. 문서를 미리 인코딩해 둘 수 있어 대규모 후보 검색에 잘 맞습니다. 반면 cross-encoder는 질의와 문서를 한 쌍으로 함께 읽고 관련성 점수를 냅니다. 원문 p.392

Bi-encoder(바이 인코더)는 반드시 서로 다른 모델 두 개를 뜻하지 않습니다. 질의와 문서를 독립적으로 처리한다는 구조를 가리킵니다. Cross-encoder(크로스 인코더)는 두 입력의 단어들이 어떻게 연결되는지도 모델 안에서 함께 평가합니다.

왼쪽: 문서와 질의를 따로 벡터로 만든 뒤 바깥에서 유사도를 계산합니다. 문서 쪽 계산은 미리 해 둘 수 있습니다. 오른쪽: 매번 질의와 문서를 함께 넣고 점수를 받습니다. 문서만으로 최종 점수를 미리 계산해 둘 수 없습니다.

그림의 0.8030과 0.0530은 같은 텍스트 쌍을 서로 다른 방법으로 평가한 예입니다. 큰 숫자가 나온 방법이 더 정확하다는 뜻이 아닙니다.

문서가 100만 개라고 해 봅시다. Bi-encoder는 문서 벡터를 미리 만들어 둡니다. 질의 시점에 새로 인코딩하는 텍스트는 검색어 하나이고, 이후 저장된 벡터를 탐색합니다. Cross-encoder를 전체 문서에 쓰면 질의와 100만 문서의 쌍을 각각 모델로 처리해야 합니다. 먼저 후보 50개를 찾으면 이 비싼 작업을 50쌍에만 적용할 수 있습니다.

“mountain hike”와 “first time snow hiking”는 둘 다 하이킹이므로 bi-encoder에서 가까울 수 있습니다. Cross-encoder는 두 입력을 함께 보면서, 산악 하이킹을 찾는 질의와 초보자의 눈길 하이킹 문서 사이의 차이를 더 세밀하게 점수화할 수 있습니다. 실제 적합성은 문서 내용과 학습 데이터에 달려 있습니다.

11 / 다시 읽기

이 여섯 가지를 설명할 수 있으면 된다

  1. 임베딩: 문서와 질의를 비교하려면 같은 의미 공간에 있어야 한다.
  2. 유사도: 두 벡터가 단위 정규화되어 있으면 코사인을 내적으로 계산할 수 있다.
  3. 자동완성 → 문서 검색: 검색 대상이 개념에서 제목으로 바뀌어도 인코딩·색인·최근접 검색의 흐름은 같다.
  4. ANN·양자화·MRL: 각각 비교할 후보 수, 표현의 비트 수, 사용하는 차원 수를 줄인다.
  5. 후보 확대 + 재랭킹: 더 많은 후보를 가져온 뒤 정밀하게 정렬하면 압축의 손실을 일부 회복할 수 있다. 후보 밖 문서는 회복할 수 없다.
  6. Bi / Cross: 따로 인코딩하면 미리 계산하기 쉽고, 함께 인코딩하면 질의·문서의 상호작용을 더 세밀하게 볼 수 있다.

스스로 확인해 보기

768차원 벡터의 길이를 1로 만들면 숫자가 하나만 남을까?

아니요. 768개의 숫자는 그대로 남습니다. 같은 비율로 값을 조절해 화살표의 크기를 1로 맞춥니다. 숫자 칸을 줄이는 MRL과 다른 작업입니다.

질의를 encode할 때 모델을 다시 학습할까?

아니요. 이 장에서는 이미 학습된 모델을 불러와 벡터를 계산합니다. 모델의 가중치를 바꾸는 학습과, 준비된 모델로 결과를 구하는 사용 단계를 구분해야 합니다.

차원이 모두 768이면 서로 다른 모델의 벡터도 비교할 수 있을까?

아니요. 배열 길이가 같다는 것과 같은 의미 공간에 놓였다는 것은 다릅니다. 호환되는 인코더와 처리 방식을 사용해야 합니다.

Binary 출력의 128과 MRL의 128은 무엇이 다를까?

원문의 Binary 128은 1,024비트를 묶은 바이트 수입니다. MRL 128은 앞쪽에 남긴 차원 수입니다.

왜 상위 25개만 원래 벡터로 다시 정렬하지 않고 50개를 가져올까?

압축·근사 검색에서 순서가 밀린 유용한 문서가 26~50위에 있을 수 있기 때문입니다. 후보를 늘려야 그런 문서가 최종 25위 안으로 올라올 기회를 얻습니다.

Cross-encoder로 문서 전체를 처음부터 검색하면 안 될까?

질의가 올 때마다 모든 문서와의 쌍을 모델에 넣어야 해 계산 부담이 큽니다. 원문은 빠른 검색으로 후보를 줄인 뒤 소수에 적용하는 방식을 제시합니다.

이 장의 실험에서 recall 100%이면 사용자에게 완벽한 검색일까?

아니요. 여기서는 원래 벡터의 정밀 검색 결과를 얼마나 유지했는지 측정했습니다. 정밀 검색 자체가 유용하지 않은 문서를 높게 평가하면, 그 결과를 100% 재현해도 좋은 검색이라고 할 수 없습니다.

정밀 벡터 재랭킹과 cross-encoder 재랭킹은 목적이 어떻게 다를까?

앞의 재랭킹은 압축·근사 때문에 흐트러진 결과를 원래 벡터의 기준에 가깝게 복구합니다. 뒤의 재랭킹은 질의와 문서를 함께 읽어 관련성 판단 자체를 더 세밀하게 합니다. 둘 다 후보 밖의 문서를 새로 찾지는 못합니다.
