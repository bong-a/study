01 / 10.1 · WHAT IS LTR?

수동으로 조절하던 가중치를 학습한다

매일 들어오는 검색어는 다양하고, 한 번만 등장하는 검색어도 많습니다. 원문의 polar m430 running watch charger, weird bump on nose - cancer?, william shatner first film처럼 클릭 기록이 드문 검색도 좋은 결과를 내야 합니다. LTR은 개별 검색어의 정답을 외우기보다, 관련성에 반복해서 나타나는 패턴을 배웁니다. 원문 p.254

10.1.2 · 실서비스 LTR의 여섯 단계

운영에서는 학습 → 모델 배포 → 검색 결과 점수화·재정렬로 이어집니다. 원문은 검색 엔진 안에서 모델을 실행해 문서와 특징을 외부로 옮기는 비용을 줄이고, 빠른 1차 검색 뒤 일부 후보만 재정렬하는 구성을 설명합니다.

1관련성 판정 수집검색어·문서·정답 등급으로 정답표를 만듭니다.
2특징 로깅각 문서의 제목 점수·줄거리 점수·개봉 연도를 채웁니다.
3학습 문제로 변환표준화하고, 같은 검색어 안의 문서 쌍을 비교합니다.
4모델 학습과 평가가중치를 배우고, 보지 못한 검색어로 검증합니다.
5모델 업로드특징 정의·표준화 통계·가중치를 검색 엔진에 등록합니다.
6검색에 적용검색 결과를 점수화하거나, 1차 검색 결과를 재정렬합니다.

원문 Figure 10.1을 읽기 순서에 맞춰 재구성했습니다. 평가 결과가 나쁘면 1–3단계로 돌아가 개선합니다. 원문 p.257

02 / 10.2 · JUDGMENT LIST

정답은 “이 검색어에 이 문서가 관련 있는가?”

Judgment list는 검색어와 문서의 조합마다 관련성 등급을 붙인 정답표입니다. 이 장에서는 1 = 관련 있음, 0 = 관련 없음으로 단순화합니다. 영화 자체의 좋은 정도가 아니라, 특정 검색어에 대한 관련성을 평가합니다. 원문 p.259

from ltr.judgments import Judgment

sample_judgments = [
    # for 'social network' query
    Judgment(1, "social network", 37799),  # The Social Network
    Judgment(0, "social network", 267752), # #chicagoGirl
    Judgment(0, "social network", 38408),  # Life As We Know It
    Judgment(0, "social network", 28303),  # The Cheyenne Social Club

    # for 'star wars' query
    Judgment(1, "star wars", 11),         # Star Wars
    Judgment(1, "star wars", 1892),       # Return of the Jedi
    Judgment(0, "star wars", 54138),      # Star Trek Into Darkness
    Judgment(0, "star wars", 85783),      # The Star
    Judgment(0, "star wars", 325553)      # Battlestar Galactica
]

qid는 같은 검색어를 묶는 식별자이고, features는 그 검색어와 문서의 특징 벡터입니다. 처음에는 비어 있는 특징을 다음 단계에서 채웁니다. 작은 예제에서는 social network의 qid가 1이지만, 확장된 데이터에서는 11로 등장합니다. 서로 다른 데이터 묶음의 ID이므로 혼동하지 않습니다.

이 장은 수동 판정으로 원리를 익힙니다. 실제로 클릭에서 대량의 판정을 만드는 click model은 11장의 주제입니다. 클릭을 곧바로 완벽한 정답이라고 가정하지 않습니다.

03 / 10.3 · FEATURE LOGGING

관련성의 단서를 세 개의 숫자로 표현한다

특징(feature)은 문서, 검색어, 또는 둘의 관계를 나타내는 숫자입니다. 이 장의 벡터 순서는 항상 [title_bm25, overview_bm25, release_year]입니다. BM25는 텍스트의 키워드 일치를 점수화하는 방법입니다. 원문 p.260

이 장에서 사용한 특징 3개
특징무엇을 묻는가검색어에 따라 변하나?
title_bm25제목이 검색어와 얼마나 잘 맞는가?예 · 검색어–문서 관계
overview_bm25줄거리가 검색어와 얼마나 잘 맞는가?예 · 검색어–문서 관계
release_year언제 개봉한 영화인가?아니요 · 문서 속성

10.3.1 · 특징의 계산 방법을 저장한다

검색 엔진의 feature store에 특징 이름과 계산 방법을 저장합니다. 그 정의를 사용해 학습 데이터를 로깅하고, 나중에 실제 검색도 처리해야 합니다. 학습 때와 서비스 때 특징 계산이 같아야 학습한 규칙을 그대로 적용할 수 있습니다.

Listing 10.4 · 세 특징을 feature store에 등록하기
원문 코드 · 서식 정리 · 원문 p.261
feature_set = [
    ltr.generate_query_feature(feature_name="title_bm25",
                               field_name="title"),
    ltr.generate_query_feature(feature_name="overview_bm25",
                               field_name="overview"),
    ltr.generate_field_value_feature(feature_name="release_year",
                                     field_name="release_year")]

ltr.upload_features(features=feature_set, model_name="movie_model")
display(feature_set)

04 / 10.4.1–10.4.2 · NORMALIZATION

제목 점수와 개봉 연도에 같은 눈금을 쓴다

먼저 SVM은 두 집단을 나누는 경계를 학습하는 분류기라고 생각하면 됩니다. 원문은 고양이와 개를 키·몸무게로 구분하는 예를 듭니다. 이 장에서는 뒤에서 만들 문서 쌍의 +1/−1을 구분합니다. 키를 cm에서 mm로 바꾸면 숫자의 눈금이 달라지듯, 특징 단위가 제각각이면 학습에 영향을 줍니다.

제목 BM25는 한 자릿수인데 개봉 연도는 2000 안팎입니다. SVM은 특징의 스케일에 민감하므로 각 특징을 비교 가능한 크기로 바꿉니다. 원문은 이를 normalization이라 부르며, 사용하는 방법은 평균을 빼고 표준편차로 나누는 표준화(z-score)입니다. 원문 p.267

z = (x − μ) / σx: 원래 값 · μ: 해당 특징의 평균 · σ: 해당 특징의 표준편차
0은 평균, +1은 평균보다 1 표준편차 큼, −1은 1 표준편차 작음.

05 / 10.4 · SVMRANK 핵심

“A가 B보다 위”를 분류 문제로 바꾼다

일반적인 점별 예측(pointwise)은 주가처럼 각 대상의 값을 맞힙니다. 검색은 같은 검색어로 모인 결과들의 순서가 중요합니다. 서로 다른 검색어의 점수를 직접 비교하는 것이 목표가 아닙니다. 원문 p.264

어려운 순위 문제를 쉬운 질문으로 나누기

① 같은 검색어social network의
관련·비관련 영화 선택
→
② 특징끼리 뺄셈Δz = zA − zB
표준화된 특징의 차이
→
③ 방향에 라벨A가 더 관련: +1
A가 덜 관련: −1

이것이 pairwise transformation입니다. 두 문서의 등급이 같으면 이 예제에서는 비교를 추가하지 않습니다. 이렇게 만든 feature_deltas와 predictor_deltas를 일반적인 이진 분류기인 SVM에 입력합니다. +1과 −1은 영화의 원래 grade가 아니라, 비교 방향의 라벨입니다.

핵심 연결: 순서 문제 → 차이 벡터의 분류 문제.

같은 검색어의 두 문서에서 표준화된 특징을 빼고, 더 관련 있는 문서가 앞이면 +1, 뒤면 −1을 붙입니다. SVM은 이 비교들을 구분하는 규칙을 배웁니다.

참고 · 다른 LTR 모델도 같은 방식일까요?

모든 LTR이 이 변환을 그대로 사용하는 것은 아닙니다. 이 장은 SVMrank로 원리를 보여줍니다. 원문이 함께 언급하는 LambdaMART는 트리 기반 모델이며, 문서 쌍의 순서를 바꿀 때 DCG가 얼마나 달라지는지 활용합니다.

DCG는 관련 있는 문서가 상위에 놓일수록 더 높게 평가하는 순위 지표입니다. 이 설명은 용어를 이해하기 위한 보충이며, 지금은 SVMrank의 흐름을 이해한 뒤 다음 절로 넘어가도 됩니다.

06 / 10.5.1–10.5.2 · TRAIN & SCORE

학습된 방향이 곧 특징의 가중치가 된다

분리 경계에 수직인 벡터 w는 +1 쪽, 즉 더 관련 있는 방향을 가리킵니다. 이 벡터의 각 성분을 특징의 가중치로 사용합니다. 2차원 공간에서는 경계가 선이고, 일반적으로 n차원 공간의 초평면은 n−1차원입니다. 원문 p.275

score(q, d) = w · z(q, d)
= wtitleztitle + woverviewzoverview + wyearzyearq: 검색어 · d: 문서 · z: 표준화된 특징 벡터 · 점수가 큰 문서를 먼저 표시.

왜 쌍으로 배운 것을 문서 하나에 쓸 수 있을까요? w·(zA−zB) = w·zA−w·zB이기 때문입니다. 차이의 점수가 양수라면 A의 점수가 B보다 큽니다. 공통 절편을 더하더라도 같은 검색어 안의 순위에는 영향을 주지 않아, 이 예제는 계수의 가중합으로 순위를 정합니다. 대규모 커머스의 학습·페이징 설계 →

Listing 10.15 · 평가 검색어별 Precision@5를 구하고 평균내기
원문 계산식 유지 · itertools.groupby 전에 qid 정렬을 추가 · 원문 p.278
from itertools import groupby

def score_one(features, model):
    score = 0.0
    for idx, f in enumerate(features):
        this_coef = model.coef_[0][idx].item()
        score += f * this_coef
    return score

def rank(query_judgments, model):
    for j in query_judgments:
        j.score = score_one(j.features, model)
    return sorted(query_judgments, key=lambda j: j.score, reverse=True)

def evaluate_model(test_data, model, k=5):
    total_precision = 0
    unique_queries = groupby(sorted(test_data, key=lambda j: j.qid),
                             lambda j: j.qid)
    num_groups = 0
    for qid, query_judgments in unique_queries:
        num_groups += 1
        ranked = rank(list(query_judgments), model)
        total_relevant = len([j for j in ranked[:k] if j.grade == 1])
        total_precision += total_relevant / float(k)
    return total_precision / num_groups

evaluation = evaluate_model(test_data, model)
print(evaluation)
# 원문 실행 결과: 0.36

원문 p.278의 “top four” 문장은 코드의 k=5 및 p.277 설명과 맞지 않아 여기서는 상위 5개로 통일했습니다. itertools.groupby는 연속된 키만 묶으므로 코드에 qid 정렬을 추가했습니다.

P@5는 상위 5개 내부의 순서를 구분하지 못합니다.

관련 문서가 1위인지 5위인지는 이 값에 반영되지 않습니다. 순위 위치와 다단계 관련성까지 중요하다면 그 목적에 맞는 지표도 검토해야 합니다. 이는 지표 해석을 위한 보충 설명입니다.

1새롭고 더 나은 특징어떤 검색어에서 실패하는지 보고 누락된 관련성 단서를 찾습니다.

스스로 답해 볼 다섯 가지 질문

1. Judgment의 0/1과 pairwise 라벨 −1/+1은 무엇이 다른가요?

0/1은 특정 검색어에 대한 문서의 관련성입니다. −1/+1은 두 문서를 뺄 때 첫 번째 문서가 두 번째보다 덜/더 관련 있는지를 나타냅니다.

2. 왜 서로 다른 검색어의 문서를 쌍으로 비교하지 않나요?

랭킹의 목표는 같은 검색어 안의 결과 순서입니다. 검색어가 다르면 비교의 기준 자체가 달라집니다. 이 장의 pairwise 변환은 같은 qid 안에서만 수행합니다.

3. 쌍으로 학습했는데 검색 시에는 왜 한 문서씩 점수를 계산하나요?

선형성 때문에 w·(A−B) = w·A−w·B입니다. 더 관련 있는 문서의 점수가 높아지도록 가중치를 배웠으므로, 각 문서를 따로 점수화하고 정렬할 수 있습니다.

4. 가중치만 검색 엔진에 복사하면 충분한가요?

아닙니다. 특징 정의와 순서, 학습에 사용한 평균·표준편차도 일치해야 합니다. 표준화된 값으로 배운 모델에 원시 값을 바로 곱하면 다른 계산이 됩니다.

5. LTR이 정확하면 재정렬 후보 수는 적어도 괜찮을까요?

후보에 들어오지 못한 문서는 재정렬할 수 없습니다. 후보 검색의 품질, 재정렬 깊이, 지연 시간을 함께 측정해야 합니다.
