AI 기반 검색이란 무엇인가

검색창은 이제 모든 앱의 기본 인터페이스가 되었다. 이 장에서는 "AI 기반 검색"이 전통적인 검색과 무엇이 다른지, 사용자 의도를 어떻게 이해하는지, 그리고 실제로 어떤 구성 요소들이 모여 스스로 학습하는 검색 시스템을 만드는지를 개념 중심으로 정리한다.

AI 기반 검색의 정의 사용자 의도 이해 동작 원리 콘텐츠 · 행동 인텔리전스 아키텍처

검색은 "관련성 튜닝"을 사람이 수작업으로 하던 일에서, 콘텐츠와 사용자 신호를 스스로 학습해 계속 좋아지는 시스템으로 진화하고 있다 — 단, 그 자동화 안에는 항상 사람이 검증·개입할 수 있는 여지를 남겨둔다.

Glossary

핵심 용어 정리

본문에서 반복해서 등장하는 용어를 먼저 훑어보면 이후 내용이 훨씬 쉽게 읽힌다.

AI 기반 검색AI-powered search

도메인·사용자·콘텐츠를 자동으로 학습해 관련성을 계속 스스로 개선하는 검색 시스템.

RAGRetrieval Augmented Generation

검색 엔진을 지식 소스로 써서 LLM에 정확하고 최신인 맥락을 제공해 환각을 줄이는 기법.

LLM · 파운데이션 모델Foundation model

방대한 텍스트로 학습한 대형 신경망. 이해·생성·요약·분류에 두루 쓰이는 범용 모델.

임베딩Embedding

텍스트·이미지 등 콘텐츠의 의미를 담은 숫자 벡터. 의미 기반 유사도 검색에 사용된다.

신호Signal

클릭, 좋아요, 구매, 체류 시간 등 사용자와 검색 결과의 모든 상호작용 데이터.

부스트Boost

특정 신호나 필드에 곱하는 가중치. 최종 랭킹 점수에서 그 신호의 중요도를 결정한다.

Learning to RankLTR

사람이 부스트 값을 직접 정하는 대신, 머신러닝이 최적 가중치를 자동으로 학습하는 랭킹 기법.

반영된 지능Reflected intelligence

사용자 행동 → 신호 수집 → 모델 개선 → 결과 반영으로 이어지는 지속적 피드백 루프.

개인화 스펙트럼Personalization spectrum

전통적 키워드 검색부터 전통적 추천까지, 프로필 반영 정도에 따라 이어지는 연속선.

시맨틱 검색Semantic search

문자열이 아니라 엔터티·개념 등 "의미"를 기준으로 문서를 찾는 검색 방식.

지식 그래프Knowledge graph

엔터티와 그 관계를 표현한 그래프. 도메인 이해와 시맨틱 검색의 기반이 된다.

시맨틱 지식 그래프SKG

이 세상의 사물(엔터티)들이 서로 어떻게 연결되어 있는지를 컴퓨터가 사람 대신 자동으로 학습해서 만든 그래프.

구문 탐지Phrase detection

두 단어가 우연보다 훨씬 자주 붙어 나타나는지 통계로 판단해, 하나의 의미 단위(구)인지 확인하는 기법.

패싯 검색Faceted search

검색 결과를 브랜드·가격 등 속성(Facet)별로 나눠, 사용자가 조건을 좁혀가게 하는 필터 검색.

콘웨이의 법칙Conway's Law

시스템 구조는 그 시스템을 설계한 조직의 소통 구조를 그대로 닮는다는 법칙.

추출적 vs 추상적 질의응답Extractive / Abstractive QA

추출적은 문서 속 문장을 그대로 반환, 추상적은 여러 문서를 종합해 새 문장을 생성한다.

관련성 엔지니어링Relevance engineering

필드 가중치, 부스트, 텍스트 분석 등을 조정해 검색 관련성을 수작업으로 튜닝하는 전문 분야.

Why now

왜 지금 "AI 기반 검색"인가

검색은 더 이상 구글 같은 웹 검색만을 뜻하지 않는다. 쇼핑, 동영상 추천, 이메일 정렬, 뉴스 피드까지 — 우리가 매일 만나는 대부분의 디지털 경험은 결국 검색되고 순위가 매겨진 콘텐츠를 보여주는 것이다. 그리고 ChatGPT, Claude, Gemini 같은 대형 언어 모델 (LLM)의 등장으로, 이 검색 기술에 대한 사용자의 기대치는 과거 어느 때보다 높아졌다.

과거의 검색이 "파란 링크 10개"를 나열하는 것이었다면, 오늘날 사용자는 검색 엔진이 다음과 같기를 기대한다.

도메인 인식적 (Domain-aware)

일반적인 문자열 통계가 아니라, 해당 분야의 엔터티·용어·카테고리를 이해한다.

맥락적 · 개인화 (Contextual)

사용자 맥락, 이전 검색, 프로필과 도메인 맥락(재고, 비즈니스 규칙)을 함께 고려한다.

대화형 (Conversational)

자연어로 대화하며 다단계 탐색 과정을 안내하고, 그 과정에서 새로운 정보를 학습한다.

멀티모달 (Multi-modal)

텍스트, 음성, 이미지, 영상 등 여러 형태의 질의를 이해하고 상호 검색한다.

지능적 (Intelligent)

철자 교정, 구문·속성 감지, 의도 분류 등으로 사용자가 "의미하는 바"를 이해한다.

어시스티브 (Assistive)

단순 링크가 아니라 답변, 요약, 설명, 실행 가능한 액션까지 제공한다.

왜 중요한가

오늘날 최고의 LLM조차 정보 소스에 근거하지 않으면 환각(hallucination)을 일으킨다. 그래서 검색 엔진이나 벡터 데이터베이스를 지식 소스로 활용해 LLM에 정확하고 최신인 맥락을 제공하는 기법인 검색 증강 생성(RAG)이, 생성형 AI의 정확도를 높이는 가장 신뢰할 수 있는 방법 중 하나로 떠올랐다.

1.1

AI 기반 검색이란 무엇인가

AI · 머신러닝 · 딥러닝 · 검색은 어떻게 겹치는가

소프트웨어 개발 맥락에서 인공지능(AI)은 "과거에는 사람의 지능이 필요했던 작업을 수행하는 프로그램"을 뜻한다. 규칙 기반 시스템도 AI로 간주되지만, 이 책은 주로 데이터를 학습해 스스로 성능을 개선하는 머신러닝 기반 AI를 다룬다.

검색(search)은 질의에 맞는 문서를 찾는 매칭(matching)과 관련도 순으로 정렬하는 랭킹(ranking)이라는 두 핵심 단계로 이루어진다. 여기에 질의를 이해하는 전처리, 답을 추출·요약하는 후처리가 더해진다.

네 영역의 관계

AI, 데이터 과학, 머신러닝, 딥러닝, 검색은 서로 포함 관계이거나 교집합 관계를 이룬다.

이 책의 초점은 검색(정보 검색)과 AI의 교집합, 특히 머신러닝·딥러닝 기법으로 검색 결과의 관련성을 높이고, 관련성 튜닝 과정을 자동화하는 데 있다.

AI 기반 검색 기법의 세 층위

이 책이 다루는 기법들은 아래처럼 AI 전용 / 머신러닝 / 딥러닝 층위로 나눌 수 있다.

AI 전용 기법

  • 질의응답 시스템
  • 가상 비서 / 챗봇
  • 규칙 기반 관련도 튜닝

머신러닝 (ML)

  • 신호 부스팅 모델
  • Learning to Rank
  • 협업 필터링 · 개인화
  • 콘텐츠 클러스터링
  • NLP / 엔티티 해석
  • 시맨틱 지식 그래프

딥러닝 (DL)

  • 파운데이션 모델 / LLM
  • 신경망 검색 · 벡터 검색
  • 워드 임베딩
  • 멀티모달 검색(이미지·영상)
  • 생성형 검색 · 요약
핵심 포인트

규칙 기반 챗봇처럼 머신러닝 없이도 AI로 부를 수 있는 기법이 있는 반면, 신호 부스팅·랭킹 학습·지식 그래프 학습처럼 사용자 행동 신호(클릭, 좋아요, 구매 등)로 데이터를 학습하는 순간 머신러닝 영역에 들어선다. 그리고 신경망으로 텍스트·이미지의 의미를 학습해 임베딩을 생성하고, 답을 생성·요약하는 단계가 딥러닝 영역이다.

파운데이션 모델(LLM)은 방대한 인간 지식을 압축해 담고 있지만, 이는 손실 압축이라 원본 사실이 그대로 저장되지 않아 환각이 발생하기 쉽다. 그래서 검색 엔진이 사실 기반 지식 소스 역할을 하는 RAG가 중요해진다.

1.2

사용자 의도 이해하기

검색엔진과 추천엔진은 사실 같은 문제의 양 극단이다

1.2.1검색 엔진이란?

검색 엔진은 보통 텍스트박스에 질의를 명시적으로 입력하고 응답을 받는 기술로 여겨진다. 결과는 리스트로 반환되고, 추가 필터링 옵션이 함께 제공된다. 한 검색 세션이 끝나면 사용자는 대개 이전 검색 맥락 없이 새 질의로 다시 시작한다.

검색 엔진은 소프트웨어 공학에서 가장 크로스펑셔널한 시스템 중 하나다. 수백만~수조 개 문서에 대해 수백 밀리초 안에 응답해야 하는 대규모 확장성, 역색인이나 ANN 기반 벡터 저장소 같은 검색 전용 자료구조, 선형대수·벡터 유사도 채점, 텍스트 분석과 자연어 처리 지식이 두루 필요하다. 검색 엔진이 제공하는 대표적인 기능으로는 철자 교정, 자동완성, 패싯(faceting), 텍스트 하이라이팅, 임베딩 등이 있다.

실무 개념패싯 검색(Faceted Search)이란?

패싯 검색은 검색 결과를 여러 속성(Facet)으로 분류해, 사용자가 원하는 조건으로 점점 좁혀가게 하는 검색 방식이다. 쉽게 말하면 필터 검색이다.

1.2.2추천 엔진이 제공하는 것

추천 엔진은 직접적인 사용자 입력 없이, 시스템이 사용자에 대해 학습한 것을 바탕으로 콘텐츠를 전달한다. 관심사는 사용자 선호, 행동, 조회 이력 등을 통해 추론된다. 아마존의 "이 상품에 관심 있으셨다면…" 섹션이 대표적 예이며, 이런 추천은 기업 매출에 직접 기여하는 동시에 사용자가 명시적으로 찾던 것을 보완하는 관련 콘텐츠를 발견하게 돕는다.

  • 콘텐츠 기반 추천 — 아이템·사용자의 속성을 기준으로 매칭한다.
  • 행동 기반 추천 — 비슷한 사용자·아이템 간 상호작용의 중첩을 기준으로 매칭한다.
  • 멀티모달 추천 — 콘텐츠 속성과 행동 중첩을 함께 사용하는 하이브리드 방식이다.

검색 엔진 (Search)

  • 사용자가 명시적으로 질의를 입력
  • 결과 목록 + 필터링 옵션 제공
  • 이전 검색 맥락 없이 매 세션 새로 시작
  • 역색인, ANN 벡터 저장소 등 대규모 인프라 필요

추천 엔진 (Recommendation)

  • 직접적인 질의 입력 없이 동작
  • 선호·행동·조회 이력으로부터 추론
  • 콘텐츠 기반 / 행동 기반 / 멀티모달 방식으로 구분
  • 전자상거래 매출에 직접 기여

한눈에 비교 — 두 기술은 겹치는 목표를 서로 다른 입력 방식으로 푸는 것뿐이다.

많은 조직이 검색팀과 추천팀을 완전히 별개 조직으로 운영한다(각각 엔지니어링, 데이터 사이언스 배경). 이는 콘웨이의 법칙에 따라 두 기술이 만나야 할 중간 지점, 즉 "개인화"에서 오히려 취약점을 만든다.

더 알아보기콘웨이의 법칙(Conway's Law)이란?

"시스템을 설계하는 조직은 그 조직의 소통 구조를 그대로 닮은 시스템을 만든다." 쉽게 말해 조직 구조 = 시스템 구조다.

예시
검색팀 · 추천팀 · 결제팀이 따로 소통

팀이 서로 분리되어 있으면, 시스템도 검색 서비스 · 추천 서비스 · 결제 서비스로 나뉘어진다.

검색 플랫폼팀 하나가 검색엔진·API·DB를 모두 담당

같은 팀이 소통하며 만들면, 검색엔진 → 검색 API → 검색 DB가 하나의 응집된 서비스가 된다.

왜 그럴까

개발자는 자주 이야기하는 사람들과 같이 코드를 만든다. 그래서 조직의 소통 구조가 곧 서비스의 경계가 된다.

이렇게 나뉜 이유는 기술적 필요 때문일 수도 있지만, 대부분은 검색팀·Core팀·Feed팀처럼 조직이 이미 그렇게 나뉘어 있기 때문이다.

핵심 — 좋은 시스템을 만들고 싶다면 조직 구조도 함께 설계해야 한다.

1.2.3개인화 스펙트럼

검색과 추천은 별개의 시스템이 아니라, "사용자 프로필을 얼마나, 어떤 방식으로 반영하는가"에 따른 하나의 연속된 스펙트럼으로 볼 수 있다.

방식프로필 사용사용자가 수정 가능
Traditional Keyword Search❌–
Personalized Search암묵적❌
User-guided Recommendation명시적✅
Traditional Recommendation명시적❌
Traditional Keyword Search

프로필을 전혀 쓰지 않고 검색어만 사용한다. 누가 검색하든 결과가 거의 같다.

검색어 "맥북" → 맥북 관련 결과 (모두 동일)
Personalized Search

검색어를 쓰되 프로필도 몰래 함께 반영한다. 같은 검색어라도 사람마다 결과가 달라진다.

"apple" · 개발자 → Apple Inc.
"apple" · 과일 애호가 → 사과
Traditional Recommendation

시스템이 알아서 추천하고, 사용자는 추천 기준 자체를 수정할 수 없다.

유튜브: 시청기록 → 자동 추천
넷플릭스: 오징어게임 시청 → 기묘한 이야기 추천
User-guided Recommendation

사용자가 추천 기준 자체를 직접 선택하고, 선택 즉시 추천이 바뀐다.

넷플릭스 가입 시 "액션 · SF" 선택 → SF 위주 추천
쇼핑몰: "러닝 · 캠핑" 관심사 선택 → 관련 추천
헷갈리기 쉬운 지점 — 유튜브 "이 영상 추천 안 함"

엄밀히 말하면 이는 User-guided Recommendation이 아니라 Traditional Recommendation + 사용자 피드백이다. 사용자는 "이 영상/채널 추천 안 함"만 선택할 수 있을 뿐, 추천 프로필 자체를 직접 편집하는 것은 아니기 때문이다. 즉 "관심 없음" 표시 → 시스템이 내부 프로필을 대신 수정 → 추천이 바뀌는 구조다.

정리하면 User-guided는 "내가 추천 기준을 직접 설정"하는 것(예: 좋아하는 장르·관심사 선택)이고, Traditional Recommendation은 "시스템이 알아서 추천하고 필요하면 피드백만 받는" 것(유튜브, 인스타그램, 틱톡 등 대부분의 피드형 서비스)이다.

★ 핵심검색과 추천은 별개가 아니다

검색과 추천은 서로 다른 기술이 아니라, "프로필을 얼마나 반영하는가"에 따른 하나의 연속된 스펙트럼일 뿐이다. 이걸 별개 조직·기술로 나누면 그 사이(개인화)를 아무도 잘 다루지 못하는 조직적 함정에 빠지기 쉽다.

1.2.4시맨틱 검색과 지식 그래프

진짜 좋은 AI 기반 검색을 만들려면 "문자열(strings)"이 아니라 "사물(things)"을 검색해야 한다. 즉 질의 속 단어를 엔터티로 해석해야 한다. 예를 들어 senior software engineer at google은 단순 키워드가 아니라 직급 · 직함 · 회사라는 의미 단위로 파싱될 수 있다. 이를 위해 도메인 고유의 구문·동의어·엔터티를 학습하고, 이들 사이의 관계를 지식 그래프로 구성해야 한다.

이 구문·용어는 사용자 검색어 로그, 통계적 구문 탐지(phrase detection), 또는 카탈로그의 구조화된 속성값에서 얻는다.

1.2.5사용자 의도의 차원 이해하기

결국 완전한 사용자 의도 이해는 콘텐츠 이해, 사용자 이해, 도메인 이해라는 세 축이 만나는 지점에서 이루어진다.

★ 핵심최종 목표

도메인에 대한 전문적 이해, 사용자와 그 취향에 대한 전문적 이해, 그리고 임의의 질의를 매칭·랭킹할 수 있는 능력 — 이 세 가지가 균형 있게 결합될 때 비로소 사용자 의도를 정확히 이해하는 검색이 완성된다.

1.3

AI 기반 검색은 어떻게 동작하는가

기본 키워드 검색에서 스스로 학습하는 플랫폼으로

조직의 검색 역량은 대체로 정해진 경로를 따라 성숙해간다. 처음에는 기본 키워드 검색을 구축한 뒤, 관련성 향상을 위해 필드 가중치·부스트를 수작업으로 튜닝한다. 이후 도메인 이해(엔터티, 동의어, 규칙)에 투자하고, 질의 의도 해석에 투자하며, 마지막에는 이 모든 과정을 자동화한 자기 학습(self-learning) 단계로 나아간다.

1.3.1핵심 검색 기반

검색 플랫폼을 구축하는 첫걸음은 거의 언제나 전통적인 키워드 검색을 돌아가게 만드는 것이다(그림 1.7의 "콘텐츠 이해" 부분). 많은 팀이 이 단계를 튜닝하는 데만 수년을 쓰며, 콘텐츠를 이해·개선하고 부스트와 질의 파라미터를 조정해 관련성을 극대화하는 관련성 엔지니어링(relevance engineering)이라는 전문 분야도 여기서 생겨났다.

관련성 엔지니어의 역할은 점차 사용자 이해·추천, 도메인 이해·시맨틱 검색 영역으로 확장된다. 이 책의 목표는 관련성을 학습하고 최적화하는 과정 자체를 지속적인 피드백 루프로 자동화하는 것 — 즉 관련성 엔지니어의 업무 상당 부분을 알고리즘이 대신하게 하는 것이다.

잘 튜닝된 검색과 AI 기반 검색의 차이

잘 튜닝된 검색 엔진은 AI 기반 검색이 세워지는 토대다. 그러나 AI 기반 검색은 여기서 한 걸음 더 나아가, 반영된 지능(reflected intelligence) — 지속적인 피드백 루프를 통해 끊임없이 배우고 개선하는 능력 — 을 갖춘다는 점에서 근본적으로 다르다.

1.3.2반영된 지능: 피드백 루프

교사도, 시험도, 동료도 없이 교과서만 읽었다면 자신이 무엇을 잘못 이해했는지 결코 알 수 없듯, 피드백 루프가 없는 검색 엔진은 같은 실수를 영원히 반복한다.

1.3.3신호(signals)로부터 배우는 세 가지 방식

검색·클릭·좋아요·장바구니·구매 등 사용자와의 모든 상호작용을 신호라고 부른다. 신호는 콘텐츠와 함께 AI 기반 검색을 움직이는 두 축 중 하나이며, 다음 세 방식으로 관련성을 학습하는 데 쓰인다.

대중적 관련성
신호 부스팅

집계된 신호를 이용해 인기 질의에 대해 가장 중요한 문서의 순위를 끌어올린다.

개인화된 관련성
협업 필터링

행렬 분해 등으로 사용자별 추천과 개인화된 검색 결과를 생성한다.

일반화된 관련성
Learning to Rank

클릭 모델 기반 관련성 판단으로 랭킹 분류기를 학습해, 처음 보는 질의에도 일반적으로 적용 가능한 랭킹 함수를 만든다.

더 알아보기Signal과 Boost, 실제로 어떻게 계산될까

신호(Signal)는 콘텐츠가 좋은지 판단하는 근거이고, 부스트(Boost)는 그 신호에 얼마만큼의 중요도를 줄지 정하는 가중치다.

클릭수조회수CTR구매수 최신성검색어 일치도개인화평점
가중치를 바꾸면 순위가 뒤집힌다
BM25 + 인기 (가중치 1:1)
상품 A90 + 20 = 110
상품 B60 + 40 = 100
결과A가 상위
BM25 + 인기 × 3
상품 A90 + 60 = 150
상품 B60 + 120 = 180
결과B가 역전
실무에서 쓰는 공식 예시
최종점수 = BM25 × 5 + CTR × 3 + Like × 2 + 최신성 × 1 + 개인화 × 4

예를 들어 "black dress"를 검색했을 때, 검색어 일치도·CTR은 높지만 좋아요는 적은 아이템과 일치도·CTR은 보통이지만 좋아요가 많은 아이템이 있다면, 위 공식에서 어떤 항목의 Boost를 더 크게 주느냐에 따라 최종 순위가 달라진다.

왜 서비스마다 다른 가중치를 쓸까

검색에서는 검색어 일치도 > 조회수가 중요하지만, 추천에서는 개인 취향 > 검색어가 더 중요하다. 그래서 서비스 목적에 맞게 신호마다 다른 Boost를 적용한다.

Learning to Rank로 가는 이유

초기에는 사람이 "BM25 × 5, CTR × 3" 처럼 가중치를 직접 정한다. 서비스가 커지면 어떤 조합이 최적인지 사람이 감으로 찾기 어려워지고, 이때 머신러닝이 "CTR은 2.8배, 최신성은 0.6배"처럼 최적 가중치를 데이터로부터 자동 학습한다 — 이것이 Learning to Rank(LTR)다.

1.3.4콘텐츠와 도메인 인텔리전스, 그리고 LLM

신호가 "행동" 데이터라면, 문서 내용 자체도 도메인을 이해하는 풍부한 정보원이다. 문서 속 엔터티, 도메인 용어, 문장들은 시맨틱 지식 그래프(SKG)의 재료가 된다. SKG란 이 세상의 사물(엔터티)들이 서로 어떻게 연결되어 있는지를 컴퓨터가 사람 대신 자동으로 학습해서 만든 그래프다.

오늘날 대부분의 LLM은 2017년 구글이 제안한 트랜스포머(Transformer) 구조("Attention Is All You Need")를 기반으로 한다. 트랜스포머는 텍스트를 임베딩 (의미를 담은 숫자 벡터)으로 인코딩하고, 디코더로 다시 텍스트를 생성할 수 있어 유사도 검색, 질의응답, 분류, 요약, 콘텐츠 생성까지 폭넓게 활용된다. 같은 질문이라도 문맥에 따라 다른 답을 내는 맥락 민감성이 특징이며, 도메인 데이터로 파인튜닝하면 특정 과업에서 훨씬 좋은 성능을 낸다.

1.3.5생성형 AI와 RAG

LLM은 세상에 대한 폭넓은 추론 능력을 갖췄지만 사실을 안정적으로 회상하지는 못한다. 그래서 검색 엔진이 검색 증강 생성(RAG) 파이프라인의 지식 소스 역할을 맡아, 정확하고 최신인 맥락을 LLM에 제공한다. 전통적인 "링크 10개" 검색에서 생성형 검색으로의 전환은 아래 네 단계로 나타난다.

① 검색 결과
"파란 링크 10개" — 출처만 보여준다
② 추출형 질의응답
실시간으로 출처에서 답을 그대로 추출
③ 결과 요약
검색 결과를 읽기 쉽게 재구성·요약
④ 생성형 질의응답
모델·검색 결과를 종합해 새 답변을 합성

그림 1.11 재구성 · 추출(extractive)은 문서 속 표현을 그대로 가져오는 것, 생성(abstractive)은 여러 결과를 해석해 새로운 문장으로 답을 합성하는 것이다.

예시로 비교해보면

질문: "김치찌개는 어떻게 만들어?"
  • 문서 A — 김치찌개는 신 김치를 볶다가 물을 붓고 끓이는 요리다.
  • 문서 B — 돼지고기나 참치를 넣으면 감칠맛이 좋아진다.
  • 문서 C — 된장이나 고춧가루를 약간 추가하면 깊은 맛이 난다.
추출적 질의응답

"김치찌개는 신 김치를 볶다가 물을 붓고 끓이는 요리다."

문서 A의 문장을 그대로 가져와 반환 — 새로운 문장 없음
추상적 질의응답

"김치찌개는 신 김치를 볶은 뒤 물을 붓고 끓이다가, 돼지고기나 참치를 넣어 감칠맛을 더하고, 된장이나 고춧가루로 깊은 맛을 내는 요리입니다."

문서 A·B·C를 종합해 만든 새 문장 — 어느 문서에도 그대로 없음

RAG(검색 증강 생성)는 바로 이 방식을 쓴다 — 검색으로 관련 문서를 찾아 LLM에 맥락으로 주면, LLM이 이를 바탕으로 위와 같은 새 문장을 합성한다.

"리커버리 슬리퍼 효능"을 검색하면 나오는 네이버의 AI 브리핑을 재구성한 화면이다.

정리하면

생성형 AI는 "AI 기반 검색"의 핵심 부품(답변 생성, 결과 요약)이고, AI 기반 검색은 "검색으로 강화된 AI"인 RAG의 핵심 부품이다. 둘 다 LLM과 파운데이션 모델을 적극 활용하며 서로를 필요로 한다.

1.3.6큐레이션 가능한 AI vs. 블랙박스 AI

딥러닝 모델은 왜 그런 예측을 했는지 사람이 이해하기 어려운 블랙박스가 되기 쉽다.

★ 핵심이 책의 철학

이 책은 딥러닝 기법을 다루되, 사람이 이해할 수 있는 형태로 지능을 표현하고, 사람이 다시 수정·보강할 수 있게 하는 것을 핵심 철학으로 삼는다. 즉 "AI가 보조하는 사람의 큐레이션" — 자동화하되 통제권은 사람이 쥐는 접근이다.

1.3.7AI 기반 검색 엔진의 아키텍처

핵심 검색 엔진(Solr, OpenSearch 등)을 중심으로, 색인 시점과 질의 시점 각각에 지능이 더해진다.

색인 시점 변환

  • LLM으로 문서 의미를 임베딩으로 변환
  • 문서 분류 및 필드 추가
  • 필드 값 정규화
  • 텍스트에서 엔터티 추출
  • 콘텐츠 클러스터링
  • 구문 탐지 · 품사(POS) 분석
  • 지식 그래프 · 외부 API 데이터 결합
  • 사실(RDF 트리플) 추출

질의 파이프라인

  • 개념·구문·엔터티 식별
  • 철자 교정
  • 동의어·개념·임베딩으로 질의 확장
  • 엔진이 이해할 수 있게 질의 재작성
  • 결과 요약 또는 답변 추출

이 모든 지능은 결국 배치 작업(이 책은 Apache Spark 사용)으로 콘텐츠와 신호를 분석해 도메인 특화 패턴을 학습하고, 이를 밀리초~초 단위 질의 응답에 활용할 수 있도록 미리 계산해두는 구조로 완성된다.

이 장의 핵심 문장

AI 기반 검색은 최신 LLM 하나를 가져다 붙이는 일이 아니다. 문서 변경과 사용자 신호의 끊임없는 흐름을 지속적으로 처리해 모델을 개선하고, 그 결과로 검색 결과를 계속 조정하며 효과를 측정하는 지속적 학습(end-to-end continuous learning) 시스템을 설계하는 일이다.

Summary

핵심 요약

01

LLM의 부상으로 검색에 대한 기대치가 도메인 인식적·맥락적·대화형·멀티모달·지능적· 어시스티브 수준으로 높아졌다.

02

검색과 추천은 별개의 기술이 아니라, 하나의 개인화 스펙트럼 위 두 극단이다. 그 사이 지점을 최적화하는 것이 중요하다.

03

사용자 의도를 정확히 해석하려면 콘텐츠, 사용자, 도메인을 동시에 이해해야 한다.

04

최적의 관련성은 개인화 검색(키워드 검색+협업 추천), 시맨틱 검색(키워드 검색+지식 그래프), 도메인 인식 추천 (협업 추천+지식 그래프)이 만나는 교집합에 있다.

05

AI 기반 검색은 콘텐츠와 사용자 신호라는 두 데이터 원천으로부터 학습해서 동작한다.

06

검색과 생성형 AI는 뗄 수 없는 관계다. RAG는 환각을 막기 위한 생성형 AI의 핵심 부품이고, 결과 요약 등 생성형 AI 기능은 더 나은 답을 주는 검색의 핵심 부품이다.

07

반영된 지능(reflected intelligence) — 신호를 모으고, 결과를 튜닝하고, 개선을 측정하는 피드백 루프 — 가 AI 기반 검색이 계속 똑똑해지게 만드는 엔진이다.
