11.1.1 · 관련 / 비관련에서 확률로

사람이 직접 붙인 라벨은 명시적 판정(explicit judgment)입니다. 검색·클릭 행동에서 추론한 라벨은 암묵적 판정(implicit judgment)입니다. 실제 사용자 행동을 계속 얻을 수 있으므로 최신 취향과 실제 검색 목적을 반영하고, 대규모 수동 라벨링의 비용도 줄일 수 있습니다.

다만 클릭한 이유를 확실히 알 수 없고, 사용자마다 원하는 결과도 다릅니다. 그래서 클릭 모델은 보통 0 또는 1 대신 0~1 사이의 관련성 확률을 추정한 grade를 만듭니다. 이 값은 정답을 확정하는 선언이 아니라 모델의 가정에 따른 추정치입니다.

11.1.2 · 확률 라벨도 LTR에 사용할 수 있다

방법 A

라벨을 구간으로 나누기

학습 알고리즘이 받는 등급 형식으로 변환합니다. 원문은 0.75 기준의 이진 구분, 0.25 간격의 1~4등급, 0.00~1.00을 0~100등급으로 바꾸는 방식을 예로 듭니다.

방법 B

어느 쪽이 더 큰지만 비교하기

10장의 SVMRank 방식은 두 문서의 선호 순서를 이용합니다. Return of the Jedi(0.80)가 Star Trek Into Darkness(0.20)보다 앞서야 한다고 표시하면 됩니다.

0.80 > 0.20
features(Return of the Jedi) − features(Star Trek Into Darkness)
→ 쌍별 학습 라벨 +1여기서 +1은 두 문서의 선호 방향입니다. 점수 차이 0.60 자체를 분류 라벨로 넣는다는 뜻이 아닙니다.

구간화의 정확한 경계 규칙은 구현에서 정해야 합니다. 원문의 “0.75보다 크다 / 작다” 설명에는 정확히 0.75일 때의 처리가 생략되어 있습니다.

CTR(q, d) = 클릭 수 / 해당 문서가 반환된 고유 세션 수먼저 하나의 검색어 q로 세션을 고르고, 문서 d별로 집계합니다. 분모는 전체 서비스 세션 수도, 사용자가 실제로 살펴본 횟수도 아닙니다.
Listing 11.4 · 문서별 CTR 계산
원문 코드 · 조판 줄바꿈 정돈 · 원문 p.291
def calculate_ctr(sessions):
  click_counts = sessions.groupby("doc_id")["clicked"].sum()
  sess_counts = sessions.groupby("doc_id")["sess_id"].nunique()
  ctrs = click_counts / sess_counts
  return ctrs.sort_values(ascending=False)

query = "transformers dark of the moon"
sessions = get_sessions(query, index=False)
click_through_rates = calculate_ctr(sessions)
print_series_data(click_through_rates, column="CTR")

11.2 · OVERCOMING POSITION BIAS

위치 편향: 위에 있어서 눌렀을 수도 있다

11.2.1 · 사용자는 모든 결과를 공평하게 보지 않는다

사용자는 검색엔진을 신뢰해서 상위 결과를 먼저 누르고, 위에서 아래로 훑다가 멈추며, 스크롤해야 보이는 결과까지 항상 내려가지는 않습니다. 이 때문에 같은 관련성이라도 표시 위치에 따라 클릭 기회가 달라집니다.

11.2.2 · RetroTech에서도 상위 순위에 클릭이 몰린다

모든 검색어의 세션을 모아, 각 위치의 클릭 수를 전체 고유 세션 수로 나눕니다. 0번 위치의 CTR은 약 25%, 10번 위치는 약 1.4%입니다.

11.2.3 · SDBN: ‘살펴봤을 기회’를 분모로

IMPRESSION

화면에 표시되었는가?

결과가 화면 안에 렌더링된 상태입니다. 사용자가 실제로 주의를 기울였는지는 알 수 없습니다.

EXAMINE

의식적으로 살펴봤는가?

사용자가 결과를 후보로 고려한 상태입니다. 클릭 모델은 이것을 추정해서 클릭을 해석합니다.

그림의 Nintendo 게임처럼 눈앞에 표시되어도 사용자가 못 볼 수 있습니다. 살펴보지 않은 결과의 미클릭을 곧바로 “관련 없음”으로 처리하면 부당한 감점이 됩니다.

PBM(Position-Based Model)은 위치별로 살펴볼 확률을 추정합니다. 이 장의 SDBN(Simplified Dynamic Bayesian Network) 예제는 더 단순하게 각 세션에서 가장 아래쪽의 클릭 위치와 그 위를 모두 살펴봤다고 가정합니다.

‘마지막 클릭’은 이 코드에서 가장 큰 rank입니다.

시간상 마지막 클릭을 찾는 것이 아닙니다. 클릭한 결과 중 화면상 가장 아래에 있는 위치를 찾습니다. 따라서 rank ≤ last_click_rank이면 examined=True입니다. 이는 실제 시선 기록이 아니라 모델의 가정입니다.

def calculate_examine_probability(sessions):
  last_click_per_session = sessions.groupby(
    ["clicked", "sess_id"])["rank"].max()[True]
  sessions["last_click_rank"] = last_click_per_session
  sessions["examined"] = \
    sessions["rank"] <= sessions["last_click_rank"]
  return sessions

11.3.2 · 베타 사전분포로 적게 본 결과를 완만하게 보정하기

관측이 적은 데이터를 모두 버리면 어떨까요? 문서별 관측 수는 일부에 몰리고 대부분은 적은 분포를 보입니다. 최소 횟수 기준으로 잘라내면 학습 데이터와 중요한 패턴을 많이 잃고, 중간 표본과 큰 표본의 차이도 여전히 남습니다. 이 장은 데이터를 유지하면서, 적게 본 결과는 기본 믿음 가까이에 두는 방식을 선택합니다.

① 비율 하나 대신, 그 비율에 대한 믿음을 표현하기

어떤 선수의 일반적인 타율이 0.295라고 해 봅시다. “9월, 비 오는 날, Fenway Park”에서는 3타수 2안타였더라도 곧바로 진짜 타율을 0.667로 믿기 어렵습니다. 원문은 0.295라는 기존 믿음에서 시작해, 새로운 증거가 쌓일수록 조금씩 바꾸는 직관을 사용합니다.

p ∼ Beta(a, b)
평균 = a / (a + b)a: 성공(클릭)에 해당하는 양 · b: 실패(살펴봤지만 미클릭)에 해당하는 양
사전분포의 a, b는 실제 관측 횟수일 필요가 없으며 소수도 가능합니다.

평균이 같아도 믿음의 강도는 다를 수 있습니다. 원문의 295 / (295 + 705)와 1475 / (1475 + 3525)는 모두 0.295지만, 뒤쪽은 더 큰 a+b를 가져 같은 관측 하나에 덜 흔들립니다.

그림 11.8·11.9의 같은 파라미터로 두 확률밀도를 겹쳐 그렸습니다. 세로축은 확률밀도이며 높이 자체가 확률은 아닙니다. 평균은 분포의 꼭대기 위치와도 다릅니다. 한 클릭은 분포를 오른쪽으로 조금 옮깁니다.

③ SDBN에 적용하기: 기본 점수 0.3, 사전 강도 100

이제 직관 설명용 평균 0.125에서 실제 상품 예제의 사전 평균 0.3으로 바꿉니다. prior_grade는 기본 점수, prior_weight는 그 믿음의 강도입니다. 원문은 0.3과 100을 사용하며, 모든 서비스에 고정된 정답은 아닙니다.

prior_a = prior_grade × prior_weight = 0.3 × 100 = 30
prior_b = (1 − prior_grade) × prior_weight = 0.7 × 100 = 70“성공 30, 실패 70”에 해당하는 기본 믿음에서 출발합니다. 실제로 100번 관측했다는 뜻은 아닙니다.

def calculate_prior(sessions, prior_grade, prior_weight):
  sessions = calculate_grade(sessions)
  sessions["prior_a"] = prior_grade * prior_weight
  sessions["prior_b"] = (1 - prior_grade) * prior_weight
  return sessions

def calculate_sdbn(sessions, prior_grade=0.3, prior_weight=100):
  sessions = calculate_prior(sessions, prior_grade, prior_weight)
  sessions["posterior_a"] = (sessions["prior_a"] +
                             sessions["clicked"])
  sessions["posterior_b"] = (sessions["prior_b"] +
    sessions["examined"] - sessions["clicked"])
  sessions["beta_grade"] = (sessions["posterior_a"] /
    (sessions["posterior_a"] + sessions["posterior_b"]))
  return sessions.sort_values("beta_grade", ascending=False)

bluray_sdbn_data = calculate_sdbn(sessions)

스스로 확인하기: 왜 Blu-ray 케이스는 1.0에서 0.306931로 내려갈까?

원문 설정은 prior_a=30, prior_b=70입니다. 1번 살펴보고 1번 클릭했으므로 성공 1만 추가되어 Beta(31,70)이 됩니다. 평균은 31/(31+70)=0.306931입니다. 실제 관측이 한 번뿐이라 기본 믿음의 영향이 훨씬 큽니다.

스스로 확인하기: SDBN이면 위치 편향이 완전히 사라질까?

이 장의 SDBN은 가장 아래 클릭 위쪽을 모두 살펴봤다고 가정하여 위치의 영향을 줄입니다. 실제 사용자가 건너뛰거나 다른 방식으로 탐색하면 가정과 어긋납니다. 아예 노출되지 않은 결과의 제시 편향도 해결하지 못합니다.
