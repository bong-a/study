크라우드소싱된 관련성

사용자는 검색어를 입력하고, 결과를 보고, 클릭하고, 장바구니에 담고, 구매한다. 이 장은 그 행동을 단순 로그로 남기는 데서 멈추지 않고 다음 검색의 관련도를 개선하는 학습 신호로 바꾸는 전체 과정을 설명한다.

이 장의 한 문장
좋은 검색 시스템은 사용자의 행동을 관찰하고, 그 집단적 판단을 모델로 학습한 뒤, 배운 내용을 다음 검색 결과에 되돌려준다.

사용자 행동 → 신호 수집 → 집계·학습 → 모델 배포 → 더 나은 결과 → 새로운 행동의 순환이 “반영된 지능”의 핵심이다.

Chapter Goal

검색을 스스로 조정하는 시스템으로 바꾸기

관련성을 개선할 정보는 문서 안에만 있지 않다. 사용자가 어떤 질의를 했고, 어떤 결과를 보았으며, 무엇을 클릭하거나 구매했는지는 사용자가 원한 것을 추정할 수 있는 불완전하지만 중요한 집단적 증거다. 이 장에서는 이 증거를 안정적으로 기록하고 모델로 바꾸는 방법을 배운다.

① 수집

질의·노출·클릭·장바구니·구매를 공통 신호 형식으로 남긴다.

② 연결

query_id와 사용자 식별자로 한 요청 이후의 행동을 이어 붙인다.

③ 학습

신호 부스팅, 협업 필터링, LTR처럼 목적이 다른 모델을 만든다.

④ 반영

학습한 모델을 검색에 배포하고 다시 생긴 행동으로 계속 갱신한다.

이 장을 잘 읽었다는 기준

클릭 수를 세는 코드를 외우는 것보다, 무슨 신호를 어떤 단위로 연결할지, 세 모델이 어떤 범위의 관련성을 학습하는지, 콜드 스타트와 편향이 왜 생기는지를 설명할 수 있어야 한다.

Learning to Rank
모든 질의·문서에 적용할 랭킹 규칙을 학습한다.

오탈자·구·동의어·용어 관계, 사용자 프로필, 문서 유사도도 신호에서 학습할 수 있다.

4.1.1 · Content vs. signals vs. models

검색을 개선하는 세 가지 정보원

문서는 “무엇이 있는가”를, 신호는 “사람이 무엇을 원했는가”를, 모델은 두 정보를 압축해 “어떻게 해석하고 예측할까”를 제공한다.

콘텐츠 · Content
웹 페이지, 상품, 파일, 이미지, 영상, 사실 등 검색 대상. 사용자가 찾는 정보와 답을 담는다.
신호 · Signals
질의, 노출, 클릭, 장바구니, 구매처럼 사용자가 콘텐츠와 상호작용하며 남긴 관찰값.
모델 · Models
콘텐츠와 신호로 학습한 지식 그래프, 엔티티 목록, LLM, 랭킹·추천 모델 등의 정제된 표현.
크라우드소싱 · Crowdsourcing
많은 사람의 입력을 모아 새로운 지식을 얻는 방식. 직접 평가뿐 아니라 암묵적 행동도 포함한다.
명시적 크라우드소싱

문서 수동 태깅, Mechanical Turk 작업, 오류·악성 콘텐츠 신고처럼 사용자가 의도적으로 판단을 제공한다.

암묵적 크라우드소싱

질의·노출·클릭·장바구니·구매처럼 일상 행동을 관찰해 대규모 집단 판단을 추정한다.

원문의 핵심 예시 · “driver”는 무엇을 뜻하는가?

문서에서 driver와 함께 등장하는 단어를 세면 코퍼스가 많이 보유한 의미가 드러난다. 반면 driver를 검색한 사용자의 다른 질의를 모으면 실제 사용자가 찾는 의미가 드러난다.

두 목록이 다른 이유

콘텐츠 관점은 “우리 문서에 어떤 의미가 많이 존재하는가?”에 답하고, 신호 관점은 “사용자가 어떤 의미를 많이 찾는가?”에 답한다. 검색의 목적은 사용자가 원하는 것을 보여주는 일이므로 신호가 강력하지만, 충분한 콘텐츠와 깨끗한 신호가 함께 있어야 한다.

한쪽만 사용하면 생기는 문제

콘텐츠 기반 추천은 문서 속성이 사용자에게 실제로 중요한지 모른다. 신호 기반 추천은 상호작용이 적으면 동작하지 않고, 이미 노출된 항목만 다시 추천하는 자기강화 루프를 만들 수 있다. 목표는 둘 중 하나를 고르는 것이 아니라 균형 있게 결합하는 것이다.

4.1.2 · RetroTech dataset

일관된 실습 무대: RetroTech

RetroTech는 최신 제품 대신 과거의 하드웨어·소프트웨어·음반·영상을 판매하는 가상의 전자상거래 회사다. 전자상거래는 질의부터 구매까지 행동이 명확해 신호의 가치를 설명하기 좋고, 이 책의 여러 장에서 같은 데이터로 모델을 발전시킬 수 있다.

기법 선택은 업종보다 데이터 조건에 좌우된다

이 장의 방법은 전자상거래에만 한정되지 않는다. 어떤 기법이 효과적인지는 특정 사용 사례보다 콘텐츠와 신호의 양(volume)과 다양성(variety)에 더 크게 좌우된다.

def product_search_request(query, param_overrides={}):
    request = {
        "query": query,
        "query_fields": ["name", "manufacturer", "long_description"],
        "return_fields": ["upc", "name", "manufacturer",
                          "short_description", "score"],
        "limit": 5,
        "order_by": [("score", "desc"), ("upc", "asc")]
    }
    return request | param_overrides

query = "ipod"
response = products_collection.search(**product_search_request(query))

4.1.3 · Exploring the signals data

행동을 다시 조립할 수 있게 기록한다

신호 유형마다 필요한 값은 다르다. 질의는 키워드가 필요하고, 클릭은 클릭한 문서와 그 클릭을 만든 원래 질의가 필요하다. 책은 새 신호 유형이 늘어도 처리 코드를 반복해서 바꾸지 않도록 다섯 필드의 공통 형식을 사용한다.

query_id
이 행동의 출발점이 된 특정 시점의 질의 신호 ID. 같은 검색어라도 서로 다른 실행은 다른 ID다.
user
검색 사용자를 나타내는 식별자. 로그인 ID가 없으면 더 약한 식별자로 대체한다.
type
query, results, click, add-to-cart, purchase 등 행동 종류.
target
신호가 가리키는 검색어 또는 문서. results는 순서가 보존된 문서 목록이다.
signal_time
행동이 발생한 정확한 시각. 세션 추정과 시간 가중치 계산의 근거가 된다.

query와 results를 분리

다음 페이지를 보거나 무한 스크롤로 새 결과가 노출되어도 기존 질의 행을 수정하지 않고 새 노출 신호를 추가할 수 있다.

특정 질의 실행에 연결

검색 결과는 시간에 따라 바뀐다. query_id는 키워드가 아니라 사용자가 실제로 본 결과 집합의 출발점을 가리킨다.

결과 순서를 보존

results.target은 순서 있는 목록이다. 이후 랭킹 편향과 관련성 판단을 분석할 때 노출 위치가 중요하다.

구매를 상품별로 분리

한 결제 안의 상품이 서로 다른 질의에서 왔을 수 있으므로 각 상품을 원래 query_id에 연결한다.

4.1.4 · Users, sessions, and requests

가능한 한 오래 지속되는 식별자에 연결한다

신호가 많아도 같은 사람의 연속 행동을 연결하지 못하면 의도를 배우기 어렵다. 로그인 사용자는 내부 사용자 ID가 있지만, 비로그인·공개 검색은 쿠키와 기기 단서처럼 더 유동적인 식별자가 필요하다.

User ID로그인 계정. 여러 기기를 넘어 유지되는 가장 강한 식별자.
Device ID같은 기기에서 여러 세션에 걸쳐 지속. 기기 ID 또는 IP + 기기 지문.
Browser ID같은 브라우저·앱에서 지속되는 쿠키 기반 식별자.
Session ID한 세션 동안 유지. 시크릿 모드의 세션 쿠키도 여기에 해당.
Request ID한 요청에서만 유지. 쿠키를 끄면 요청마다 새 사용자처럼 보인다.
  • 영구 쿠키가 켜져 있으면 하나의 Browser ID 아래 여러 Session ID, 그 아래 여러 Request ID가 생긴다.
  • 세션마다 쿠키를 지우면 Browser ID 하나에 Session ID 하나가 연결되지만 요청은 여러 개일 수 있다.
  • 쿠키를 끄면 요청마다 Browser ID와 Session ID가 모두 새로 생긴다.
신호 설계는 나중에 복구하기 어렵다

질의와 후속 행동을 처음부터 연결하지 않으면 AI 검색의 학습 능력이 크게 줄어든다. 타임스탬프로 세션을 추정할 수는 있지만 정보 손실을 완전히 되돌리기 어렵다. 물론 식별자 수집·보존은 개인정보 보호와 동의 정책 안에서 설계해야 한다.

4.2.1 · What is reflected intelligence?

반영된 지능: 행동을 배워 다음 결과에 돌려주기

철물점의 망치 예시

직원이 손님에게 망치가 2번 통로에 있다고 안내했다. 손님은 2번 통로에서 빈손으로 나와 5번 통로에서 망치를 들고 나왔다. 다음 날 다른 손님도 똑같이 행동했다. 그런데도 계속 2번 통로를 안내한다면 형편없는 직원이다. 기본 검색 엔진도 이전 사용자의 반응을 배우지 않으면 이 직원과 같다.

Alonzo가 ipad를 검색하고 doc22를 클릭한 뒤 구매하면, 질의·노출·클릭·구매 신호가 남는다. 다른 모든 사용자의 신호와 함께 집계하면 특정 질의의 인기 문서를 올리거나, 개인별 추천을 만들거나, 모든 검색에 통하는 문서 특징의 중요도를 학습할 수 있다.

왜 “반영된” 지능인가?

지능이 모델 안에 한 번 고정되어 있는 것이 아니라, 사용자의 집단적 판단이 시스템에 들어와 모델로 정제되고 다시 사용자 경험에 반사(reflect)되기 때문이다. 관심사와 콘텐츠가 변하면 새 신호가 모델을 다시 조정한다.

4.2.2 · Popularized relevance

신호 부스팅: 같은 질의에서 많이 선택된 문서를 올린다

인기 질의는 신호가 많이 쌓이고 사업적으로도 중요하다. 같은 질의에서 사용자가 가장 많이 클릭한 문서를 세어 해당 문서를 부스트하면, 단순하면서도 큰 개선을 얻을 수 있다. 이것이 대중화된 관련성(popularized relevance)이다.

Listing 4.5 · 부스팅 전 기본 iPad 검색
query = "ipad"
request = product_search_request(query)
response = products_collection.search(**request)
display_product_search(query, response["docs"])
원문의 ipad 실패

키워드만 사용하면 ipad를 여러 번 언급한 액세서리가 실제 iPad보다 위에 나온다. 텍스트 빈도는 “많이 언급된 문서”를 찾았지만, 사용자가 원한 상품 종류까지 이해하지 못했다.

boost(query, doc) = 동일한 query에서 doc이 클릭된 횟수
1 · 연결클릭을 같은 query_id의 질의와 조인한다.
2 · 집계질의–문서 조합별 클릭 수를 센다.
3 · 저장결과를 signals_boosting에 쓴다.
Listing 4.6 · 클릭 신호 집계 SQL 
SELECT q.target AS query,
       c.target AS doc,
       COUNT(c.target) AS boost
FROM signals c
LEFT JOIN signals q ON c.query_id = q.query_id
WHERE c.type = 'click'
  AND q.type = 'query'
GROUP BY q.target, doc
ORDER BY boost DESC
사이드카 컬렉션이란?

주 컬렉션 products 옆에서 검색을 돕는 별도 컬렉션이다. 원시 행동은 signals, 집계된 질의별 문서 부스트는 signals_boosting에 저장한다. 모델의 입력·출력을 본문 문서와 분리해 갱신하기 쉽다.

Listing 4.7 · 집계 부스트를 검색 요청에 적용 
def search_for_boosts(query, collection, query_field="query"):
    boosts_request = {
        "query": query,
        "query_fields": [query_field],
        "return_fields": ["query", "doc", "boost"],
        "limit": 10,
        "order_by": [("boost", "desc")]
    }
    return collection.search(**boosts_request)["docs"]

def create_boosts_query(boost_documents):
    return " ".join(
        [f'"{b["doc"]}"^{b["boost"]}' for b in boost_documents]
    )

query = "ipad"
boost_docs = search_for_boosts(query, signals_boosting_collection)
request = product_search_request(query)
request["query_boosts"] = create_boosts_query(boost_docs)
response = products_collection.search(**request)

4.2.3 · Personalized relevance

협업 필터링: 비슷한 사람의 선택으로 개인을 돕는다

신호 부스팅이 “모두에게 대체로 인기 있는 문서”를 찾는다면, 협업 필터링은 일부 사용자의 선호를 관찰해 다른 사용자의 선호를 예측한다. 흔히 보는 “이 상품을 좋아한 사용자가 함께 좋아한 상품”이 대표적인 결과다.

행렬이 희소하면 잠재 요인으로 압축한다

사용자–아이템 상호작용 행렬이 충분히 채워져 있으면 같은 아이템에 반응한 이웃 사용자를 직접 찾을 수 있다. 하지만 실제 행렬은 대부분 비어 있다. 이때 행렬 분해(matrix factorization)로 하나의 큰 행렬을 “사용자 → 잠재 요인”과 “잠재 요인 → 아이템” 두 행렬로 나눈다.

사용자 × 아이템 · 희소
≈
사용자 × 잠재 요인
×
잠재 요인 × 아이템

빈칸이 많은 큰 행렬을, 공유 취향을 나타내는 작은 잠재 요인 공간으로 압축한다.

사용자 × 아이템 ≈ (사용자 × 잠재 요인) × (잠재 요인 × 아이템)

잠재 요인은 사람이 미리 정한 “브랜드”나 “가격”일 필요가 없다. 사용자들이 공통으로 반응한 패턴에서 아이템의 중요한 성질이 학습된다. 문서 내용을 몰라도 행동만으로 취향과 아이템 유사성을 찾을 수 있다는 점이 협업 필터링의 힘이다.

콜드 스타트와 프레젠테이션 편향

새 문서는 신호가 없어 추천되지 않고, 추천되지 않으니 신호가 생기지 않는 모순에 빠진다. 이미 인기 있는 문서는 더 많이 노출되어 더 많은 신호를 얻는다. 이 자기강화 순환은 결과 다양성을 낮추는 프레젠테이션 편향이며, 책은 12장에서 대응한다.

4.2.4 · Generalized relevance

Learning to Rank: 관련성 판단을 일반 랭킹 규칙으로 바꾼다

신호 부스팅과 협업 필터링은 신호가 붙은 문서에 강하다. LTR은 질의와 문서의 관련성 판단 목록으로 랭킹 분류기를 학습해 아직 직접 신호가 없는 질의·문서에도 적용 가능한 관련성을 만든다.

가중치가 항상 설명 가능한 것은 아니다

단순한 랭킹 모델은 특징과 가중치를 사람이 읽을 수 있지만, 고급 딥러닝 랭킹 분류기는 반드시 해석 가능하거나 설명 가능할 필요가 없다. 모델 품질 평가와 운영 관찰이 별도로 필요한 이유다.

암묵적 판단

노출·클릭·구매 신호에서 관련성 판단을 추정한다. 두 방식을 함께 사용할 수도 있다.

세 모델의 범위를 한 문장으로

신호 부스팅은 “이 질의에서 모두가 무엇을 골랐나?”, 협업 필터링은 “이 사용자와 비슷한 사람은 무엇을 골랐나?”, LTR은 “여러 판단에서 공통으로 드러난 좋은 랭킹의 규칙은 무엇인가?”에 답한다.

4.2.5 · Other reflected intelligence models

사용자와 콘텐츠 사이의 모든 행동은 그래프의 간선이다

같은 원시 신호라도 어떻게 집계하고 학습하느냐에 따라 서로 다른 관계를 얻을 수 있다. 질의·사용자·문서·속성을 노드로 보고 행동을 간선으로 보면 활용 범위가 선명해진다.

사용자 → 문서

Alonzo에게 doc22: iPad Pro, doc12: Kindle Fire 추천.

사용자 → 선호 속성

Alonzo는 tablets, Apple, black, 32GB를 선호한다는 프로필.

문서 → 문서

doc22와 함께 선택되는 유사·관련 문서를 추천.

질의 → 문서

ipad에 doc22 0.98, doc12 0.6 같은 관련 강도.

여기에 질의 신호를 언어 데이터로 사용하면 도메인 특유의 구, 흔한 오탈자, 동의어와 관련 용어도 자동으로 찾을 수 있다. 결국 반영된 지능은 추천 모델 몇 개의 이름이 아니라, 사람이 남긴 관계를 재사용해 시스템을 학습시키는 패턴이다.

4.2.6 · Crowdsourcing from content

사용자가 만든 콘텐츠도 신호가 된다

크라우드소싱은 행동 로그에만 한정되지 않는다. 고객 리뷰의 별점은 품질 신호가 되고, 댓글의 감성 분석 결과는 긍정·중립·부정에 따라 원문 상품을 부스트하거나 패널티를 주는 신호가 된다. 스팸·악용 신고도 마찬가지다.

PageRank가 보여주는 확장된 관점

PageRank는 한 웹 페이지의 본문만 보지 않고, 다른 페이지 제작자들이 어디로 링크했는지를 집단적 판단으로 해석한다. 권위 있는 페이지가 많이 인용하는 페이지는 품질이 높을 가능성이 크다는 가정이다. 즉 링크도 사람이 콘텐츠를 만들며 남긴 암묵적 행동 신호다.

PageRank 별도 정리 보기 →
문서 내부 정보 + 문서 사이 링크 + 사용자 생성 콘텐츠 + 행동 신호 → 더 풍부한 도메인 이해

콘텐츠의 용어 사용 방식도 많은 작성자가 함께 만든 언어 데이터다. 문서 사이의 직접 링크, 댓글, 평가, 신고, 용어의 공동 출현을 모두 관계로 보면 지식 그래프와 도메인 언어 학습으로 자연스럽게 이어진다.

Summary

4장의 핵심을 다시 연결하기

01

세 가지 연료: 콘텐츠는 검색 대상을, 신호는 실제 사용자 의도를, 모델은 두 정보를 정제한 예측과 해석을 제공한다.

02

신호 설계: 질의·노출·클릭·구매를 특정 query_id, 사용자 식별자, 시각에 연결하고 결과 순서를 보존해야 나중에 올바르게 학습할 수 있다.

03

반영된 지능: 행동을 수집하고 모델을 학습한 뒤 검색에 재배포하는 피드백 루프가 사용자와 콘텐츠의 변화에 맞춰 관련성을 계속 조정한다.

04

대중화된 관련성: 신호 부스팅은 인기 질의에서 많이 선택된 문서를 올려 가장 빠르고 직접적인 개선을 만든다.

05

개인화된 관련성: 협업 필터링은 사용자–아이템 행동 패턴과 잠재 요인으로 개인의 선호와 문서 유사성을 예측한다.

06

일반화된 관련성: LTR은 판단 목록에서 랭킹 특징과 가중치를 학습하고, 보통 빠른 1차 검색의 top-N을 재랭킹한다.

07

주의점: 신호가 부족한 콜드 스타트, 이미 노출된 결과가 더 강해지는 프레젠테이션 편향, 가짜 신호와 개인정보 보호를 함께 다뤄야 한다.

08

더 넓은 활용: 리뷰·댓글·링크·용어 사용도 크라우드소싱된 지능이며 추천, 사용자 프로필, 동의어, 지식 그래프 학습으로 확장된다.
