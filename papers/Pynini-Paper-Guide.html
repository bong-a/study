규칙을 그래프로
컴파일하는 Python

Pynini는 문자열·사전·문법 규칙을 가중 유한상태 변환기(WFST)로 만드는 라이브러리다. 이 논문의 진짜 주장은 단순하다. “새 문법 언어를 또 배우게 하지 말고, 문법 객체를 Python의 일급 객체로 만들자.”

저자 Kyle Gorman 발표 ACL Workshop on Statistical NLP and Weighted Automata, 2016 분량 pp. 75–80 기반 OpenFst 1.5.3 (논문 작성 당시)

02 / 07

먼저, FST가 무엇인가

원과 화살표로 만든 작은 기계라고 생각하면 쉽다. 문자열을 읽으며 상태를 이동하고, 변환기라면 다른 문자열을 내보내며, 가중치가 있다면 여러 후보 중 더 좋은 경로를 고를 수 있다.

FSA · accept

문자열을 받아들인다

예: ab 같은 패턴이 문법에 맞는지 판정한다.

FST · transform

읽고 바꿔 쓴다

화살표의 입력:출력 라벨로 철자·발음·형태를 변환한다.

WFST · rank

후보에 비용도 매긴다

경로 가중치로 확률·비용을 표현해 최적 후보를 찾는다.

지하철 비유. 상태는 역, 화살표는 노선, 입력은 탑승 조건, 출력은 도착하며 붙이는 라벨이다. 가중치는 이동 시간이나 요금이다. 여러 노선을 겹치는 합성(composition)은 “이 노선의 도착역을 다음 노선의 출발역과 연결”하는 일과 같다.
Tropical semiring

논문의 기본 가중치 체계에서는 한 경로의 비용을 더하고, 여러 경로 중 비용이 가장 작은 것을 고른다.

03 / 07

왜 또 하나의 라이브러리인가

저자는 당시 공개 WFST 도구를 세 부류로 본다. Pynini의 자리는 강력한 알고리즘 엔진과 편한 문법 작성 경험 사이다.

도구 부류 대표 예 잘하는 것 아쉬운 점 Pynini의 선택
알고리즘 엔진 OpenFst, Carmel 결합·최적화·검색 사전/규칙을 FST로 만드는 고수준 지원이 적음 OpenFst를 실행 엔진으로 사용
문법 컴파일러 Thrax, HFST, Kleene 등 간결한 문법 기술 도구별 DSL과 연산자·우선순위를 새로 학습 별도 DSL 대신 Python 구문 사용
통합형 도구 Foma, XFST 알고리즘과 컴파일을 한곳에 제공 논문 표 기준으로 가중 변환기 지원이 없음 가중 FST와 문법 컴파일을 함께 지원
핵심 설계 철학. DSL 컴파일러가 “문법 전용 계산기”라면, Pynini는 “Python 작업대에 FST 전동 공구를 올려놓는 것”이다. XML 파싱, 파일 읽기, 반복문, 함수, 테스트 도구를 문법 작성과 한 코드 안에서 쓸 수 있다.

05 / 07

왜 optimize()가 중요한가

합성·연결·합집합을 반복하면 같은 일을 하는 상태와 간선이 늘어난다. 문제는 최적화 알고리즘마다 적용 조건이 다르다는 것. Pynini는 FST의 성질을 보고 안전한 절차를 골라주는 범용 루틴을 제공한다.

01
ε 제거

입력을 소비하지 않는 불필요한 이동을 정리한다.

02
Arc-sum 매핑

라벨이 같은 중복 간선을 가중치 규칙에 따라 합친다.

03
결정화

같은 입력에서 여러 갈래로 나뉘는 구조를 가능한 범위에서 정리한다.

04
최소화

동일한 동작을 유지하면서 상태 수를 줄인다.

컴파일러 최적화와 비슷하다. 사용자는 읽기 좋은 규칙을 조립하고, 라이브러리는 실행 전에 그래프를 작게 다듬는다. 다만 가중 순환이 있는 FST는 항상 결정화할 수 있는 것이 아니므로, Pynini는 입력 속성에 따라 우회 절차를 사용한다.
06 / 07

두 예제가 보여주는 것

논문은 규칙 중심 예제와 통계 모델 결합 예제를 나란히 둔다. 이것이 WFST의 장점이다. 작은 수작업 문법과 큰 통계 모델을 같은 그래프 연산으로 결합할 수 있다.

CASE A · FINNISH VOWEL HARMONY

핀란드어 모음조화

추상 접미사 llA의 A를 앞선 어간의 모음 문맥에 따라 a 또는 ä로 바꾼다.

  • 후설 모음: u, o, a
  • 전설 모음: y, ö, ä
  • 중립 모음: i, e
käde + llA가까운 결정 모음: ä
→
kädelläA → ä
vero + llA가까운 결정 모음: o
→
verollaA → a
stem + "llA" ∘ context-dependent rewrite → surface form
paper figure 2 · simplified reading규칙 → 합성 → 출력
# 1) A → a, 왼쪽 가까운 결정 모음이 u/o/a이면
back_rule = cdrewrite(transducer("A", "a"), back_vowel + intervener, "", sigma_star)

# 2) 나머지 A → ä
default_rule = cdrewrite(transducer("A", "ä"), "", "", sigma_star)

# 3) 두 규칙을 합쳐 표면형을 만든다
harmony_rule = (back_rule * default_rule).optimize()
surface = ((stem + "llA") * harmony_rule).stringify()

07 / 07

한계와 논문의 의의

좋은 도구 논문을 읽을 때는 “무엇을 가능하게 했나”와 “무엇까지 검증했나”를 나눠 보는 것이 중요하다.

모든 문법이 유한상태는 아니다

재귀 RTN은 유한 FST로 완전히 펼칠 수 없다. 논문은 이 경우 스택을 쓰는 PDT 컴파일을 제공한다.

성능 비교 논문은 아니다

두 사례로 표현력을 보이지만, 다른 라이브러리 대비 속도·메모리·개발 생산성의 정량 비교는 없다.

2016년 API 스냅샷이다

의존 버전과 함수명은 논문 작성 당시 기준이다. 최신 코드를 작성할 때는 현재 Pynini 문서를 별도로 확인해야 한다.

THE LASTING IDEA
“규칙”과 “통계”를 같은 가중 그래프로 바꾸면, 합성 하나로 두 세계를 연결할 수 있다.
읽고 나서 기억할 5가지
  1. FST는 문자열을 받아 다른 문자열로 바꾸는 그래프다.
  2. 가중치는 모호한 후보에 순위를 매기게 해준다.
  3. Pynini의 차별점은 전용 DSL 대신 Python 자체를 문법 작성 환경으로 삼은 것이다.
  4. cdrewrite, replace, pdt_replace가 고수준 문법을 FST/PDT로 컴파일한다.
  5. OpenFst가 하부 알고리즘을, Pynini가 개발자 경험과 컴파일 루틴을 담당한다.
정리 기준 — 논문의 주장과 예제를 중심으로 재구성했으며, 지하철·작업대 비유와 후보 비용 표시는 이해를 돕기 위한 설명이다. 코드 블록은 논문 Figure 2의 의미를 보존해 축약·주석화했으며 최신 API 사용 예제가 아니다.
