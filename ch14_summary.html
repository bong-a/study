02 · THE ORIGINAL EXAMPLE원문 데이터

QUESTIONWhat are minimalist shoes?
CONTEXT · 원문 전체 · 줄바꿈만 공백으로 정리
There was actually a project done on the definition of what a minimalist shoe is and the result was "Footwear providing minimal interference with the natural movement of the foot due to its high flexibility, low heel to toe drop, weight and stack height, and the absence of motion control and stability devices". If you are looking for a simpler definition, this is what Wikipedia says, Minimalist shoes are shoes intended to closely approximate barefoot running conditions. 1 They have reduced cushioning, thin soles, and are of lighter weight than other running shoes, allowing for more sensory contact for the foot on the ground while simultaneously providing the feet with some protection from ground hazards and conditions (such as pebbles and dirt). One example of minimalistic shoes would be the Vibram FiveFingers shoes which look like this.

유효한 시작·끝 조합 선택문맥 영역 안에서 시작 ≤ 끝 · 답 길이 제한

토큰 수가 172개면 시작 후보도 172개, 끝 후보도 172개입니다. 예를 들어 시작을 _shoes, 끝을 _conditions로 잡으면 사이의 토큰들이 정답이 됩니다. 원문에는 barefoot가 _bare와 foot로 나뉘어 나옵니다. 단어 하나가 토큰 하나라는 뜻은 아닙니다.

172는 질문 끝의 물음표가 없는 Listing 14.2 입력에 대한 원문 출력입니다. 화면의 질문은 본문 표기를 따랐습니다. 토크나이저·입력 공백·구두점이 달라지면 토큰 수와 위치도 달라질 수 있습니다.

logits와 확률은 구분해서 읽기모델의 start_logits·end_logits는 softmax 전의 점수입니다. 원문의 0~1 정규화 그림은 상대적인 강조를 보여 줍니다. 단순히 0~1로 맞춘 값을 모두 “정답일 확률”로 해석하면 안 됩니다. [보충 근거 1]

03 · RETRIEVER → READER → RERANKER원문 14.1.2 / 14.5

왜 검색과 읽기를 나누는가?

모든 문서에 QA 모델을 돌리면 느립니다. 검색 엔진으로 후보를 좁힌 뒤, 소수의 문서만 정밀하게 읽습니다.

1
Retriever — 답이 있을 법한 문서 5개 검색

질문에서 검색어를 만들고, Outdoors의 post_type=answer 문서 body를 검색합니다. 원문의 코드는 spaCy로 불용어·구두점을 제거합니다.

2
Reader — 원래 질문을 각 문서와 짝지어 읽기

검색어로 줄이기 전의 원래 질문과 각 문맥을 QA 모델에 줍니다. 구현 예제에서는 문서당 답 1개와 score, start, end를 얻습니다.

3
Reranker — 답의 score로 다시 정렬

Reader의 점수가 높은 답을 먼저 보여 줍니다. 이 장의 Reranker는 별도 학습 모델 없이 sorted(..., reverse=True)로 구현합니다.

B. Golden set을 읽고 정답 문자 위치를 만든다

CSV의 gold에는 사람이 확인한 답이 들어갑니다. 여러 허용 답은 원문처럼 |로 나눕니다. context.find(text)로 각 답의 시작 위치를 계산합니다.

B. Golden set 읽기 · 정답 위치 만들기 · 분할코드 접기 / 펼치기
PYTHON
def load_golden_data(filename):
    frame = pd.read_csv(filename)
    required = {"id", "question", "context", "gold", "class"}
    if not required.issubset(frame.columns):
        raise ValueError(f"필수 컬럼 누락: {required - set(frame.columns)}")

    # 사람 검수가 끝난 정답만 사용한다. -2를 '정답 없음'으로 간주하지 않는다.
    labels = pd.to_numeric(frame["class"], errors="coerce")
    frame = frame[labels.isin([0, 1])].copy()
    frame = frame.dropna(subset=["id", "question", "context", "gold"])
    rows = []
    for _, row in frame.iterrows():
        context = str(row["context"])  # 위치가 바뀌므로 본문은 strip하지 않는다.
        texts = [part.strip() for part in str(row["gold"]).split("|")]
        texts = [text for text in texts if text]
        starts = [context.find(text) for text in texts]
        if not texts or -1 in starts:
            raise ValueError(f"id={row['id']}: 정답이 context 안에 없습니다.")
        rows.append({
            "id": str(row["id"]),
            "title": str(row["question"]),
            "question": str(row["question"]),
            "context": context,
            "answers": {"text": texts, "answer_start": starts},
        })

    df = pd.DataFrame(rows)
    if len(df) < 20:
        raise ValueError("이 예제의 3-way 분할에는 검수된 데이터가 더 필요합니다.")
    if df["id"].duplicated().any():
        raise ValueError("동일 질문 ID가 중복됩니다. 질문 단위로 묶어 분할하세요.")
    df = df.sample(frac=1, random_state=0).reset_index(drop=True)

    # 원문 분할식: 유효한 행이 167개이면 125 / 32 / 10.
    n_train = int(len(df) * 0.75)
    cut_eval = n_train + int((len(df) - n_train) / 1.25) - 1
    pieces = {
        "train": df.iloc[:n_train],
        "test": df.iloc[n_train:cut_eval],
        "validation": df.iloc[cut_eval:],
    }
    return DatasetDict({
        name: Dataset.from_pandas(part, preserve_index=False)
        for name, part in pieces.items()
    })

datadict = load_golden_data(CSV_PATH)
print({name: len(part) for name, part in datadict.items()})

C. 윈도 생성 · 문자 위치를 토큰 위치로 변환코드 접기 / 펼치기
PYTHON
def tokenize_dataset(examples):
    features = tokenizer(
        examples["question"], examples["context"],
        truncation="only_second",  # 두 번째 입력인 context만 나눈다.
        max_length=MAX_LENGTH,     # 질문 + context + 특수 토큰을 합쳐 384.
        stride=DOC_STRIDE,         # 인접 context 조각끼리 128토큰 겹친다.
        return_overflowing_tokens=True,
        return_offsets_mapping=True,
        padding="max_length",
    )
    # 한 질문이 여러 윈도로 늘어났을 때 원본 행을 찾는 지도.
    source_rows = features.pop("overflow_to_sample_mapping")
    offsets_by_window = features.pop("offset_mapping")
    start_positions, end_positions = [], []

    for window_i, offsets in enumerate(offsets_by_window):
        answer = examples["answers"][source_rows[window_i]]
        context_tokens = [
            pos for pos, sequence_id in enumerate(features.sequence_ids(window_i))
            if sequence_id == 1  # 질문과 특수 토큰은 정답 후보에서 제외.
        ]
        left, right = context_tokens[0], context_tokens[-1]
        window_start, window_end = offsets[left][0], offsets[right][1]
        cls_pos = features["input_ids"][window_i].index(tokenizer.cls_token_id)

        # 여러 정답이 있다면 이 윈도에 완전히 들어오는 첫 정답을 사용.
        contained = [
            (start, start + len(text))
            for start, text in zip(answer["answer_start"], answer["text"])
            if window_start <= start and start + len(text) <= window_end
        ]
        if not contained:
            start_positions.append(cls_pos)
            end_positions.append(cls_pos)
            continue  # 이 조각에는 정답 전체가 없다는 학습 신호.

        start_char, end_char = contained[0]  # 문자 구간 [start, end).
        answer_tokens = [
            pos for pos in context_tokens
            if offsets[pos][0] < end_char and offsets[pos][1] > start_char
        ]
        start_positions.append(answer_tokens[0])
        end_positions.append(answer_tokens[-1])  # 마지막 토큰 자체의 인덱스.

    features["start_positions"] = start_positions
    features["end_positions"] = end_positions
    return features

# 먼저 원본 질문을 분할한 뒤, 각 split 안에서 윈도를 만든다.
tokenized_datasets = datadict.map(
    tokenize_dataset, batched=True,
    remove_columns=datadict["train"].column_names,
)
print("원본 질문 수:", len(datadict["train"]))
print("학습 윈도 수:", len(tokenized_datasets["train"]))
offset_mapping
각 토큰이 원문 context의 어느 문자 구간에 해당하는지 알려 줍니다. 이 지도와 [408,473)을 대조합니다.
source_rows
하나의 질문이 여러 윈도로 늘어나도 각 윈도가 원래 어느 질문에서 왔는지 추적합니다.
sequence_id=1
이 코드에서는 두 번째 입력인 context입니다. 질문·패딩·특수 토큰을 정답 후보에서 제외합니다.
contained
정답 전체가 이 윈도에 들어오는지 검사합니다. 일부만 들어온 답을 완전한 정답으로 학습시키지 않습니다.
CLS 위치
이 윈도 안에 정답이 없으면 시작·끝을 CLS 위치로 지정합니다. 원래 문서 전체에 정답이 있어도 개별 조각에는 없을 수 있습니다.
answer_tokens
정답 문자 구간과 겹치는 문맥 토큰을 모으고 첫·마지막 토큰 인덱스를 정답 라벨로 씁니다.
토큰 end와 문자 end는 다릅니다.문자 구간 [408,473)의 473은 제외됩니다. 반면 end_positions에는 정답 마지막 토큰의 인덱스 자체를 넣습니다. 학습용 토큰 위치는 윈도마다 달라질 수 있어 여기서 임의의 숫자를 만들지 않았습니다.
전처리 출력의미한 배치의 형태
input_ids질문 + 문맥의 토큰 번호[batch, 384]
attention_mask실제 토큰 1 / 패딩 0[batch, 384]
start_positions정답 첫 토큰의 위치[batch]
end_positions정답 마지막 토큰의 위치[batch]

길이를 맞추기 위해 padding="max_length"를 사용합니다. 토큰 ID가 모델 안에서 벡터로 바뀌므로, 토크나이저가 곧바로 768차원 임베딩을 반환하는 것은 아닙니다. 토큰화된 샘플 수는 원본 질문 수보다 커질 수 있습니다. [보충 근거 2]

학습한 Reader를 검색에 연결하기

학습이 끝나면 검색 결과 각각을 question + context로 Reader에 넣습니다. 문서 ID와 URL을 붙여 두면 사용자가 답의 출처로 이동할 수 있습니다.

Listings 14.15–14.18의 핵심 흐름을 한 함수로 재구성코드 접기 / 펼치기
PYTHON
# outdoors_collection: 원문에서 미리 구축한 Solr 검색 컬렉션
# get_query_from_question: spaCy로 불용어·구두점을 제거하는 전처리 함수
# qa: 위에서 로드한 파인튜닝 QA pipeline

def ask(question):
    docs = outdoors_collection.search(
        query=get_query_from_question(question),
        query_fields=["body"],
        return_fields=["id", "url", "body"],
        filters=[("post_type", "answer")],
        limit=5,
    )["docs"]

    answers = []
    for doc in docs:
        result = qa(question=question, context=doc["body"])
        result.update({"id": doc["id"], "url": doc["url"]})
        answers.append(result)

    return sorted(answers, key=lambda item: item["score"], reverse=True)

연결 코드에는 원문 노트북에서 준비한 검색 컬렉션과 쿼리 전처리 함수가 필요합니다. 독립 실행 예제는 아니며 A–F 코드 전체 복사에는 포함하지 않았습니다.

정답이 없는 질문도 바로 처리할 수 있나?

SQuAD2 계열 모델이라고 자동으로 운영 정책까지 해결되지는 않습니다. 윈도에 답이 없는 경우의 라벨, 실제 질문에 답이 없는 데이터, 추론 단계의 no-answer 설정과 임계값을 함께 설계해야 합니다. 이 문서의 코드는 원문의 정답 추출 흐름을 설명하며, 완성된 서비스용 답변 거절 정책은 포함하지 않습니다.

학습 데이터 125개면 서비스에 충분한가?

원문도 작은 교육용 실험이라고 밝힙니다. 책은 500~2,000개 라벨을 하나의 경험칙으로 제시하지만, 필요한 양은 도메인·질문 다양성·목표 품질에 따라 달라집니다. 특히 어떤 질문에서 틀리는지 분석하며 데이터를 추가해야 합니다.

BM25를 벡터 검색으로 바꾸면 파인튜닝도 달라지나?

Reader의 입력 형식은 그대로 질문·문맥 쌍입니다. 다만 검색 방식이 바뀌면 들어오는 문맥의 분포와 오답 후보가 달라지므로, 전체 시스템 평가는 다시 해야 합니다. Retriever와 Reader를 별도로 측정하면 어느 단계가 병목인지 확인하기 쉽습니다.

이 장에서 기억할 문장좋은 문서를 가져오는 일과, 그 문서에서 좋은 답을 고르는 일을 나눠 설계한다. 그리고 모델에 정답을 가르치는 데 필요한 가장 중요한 자산은 사람이 확인한 질문·문맥·정답 구간이다.
