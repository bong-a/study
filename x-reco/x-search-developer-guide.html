CHAPTER 00 · THE BIG LESSON

가져올 것은
거대한 모델이 아니다

X 저장소는 모델 전시장이기보다 온라인 후보 수집→정밀 평가→정책 판단을 분리한 제품 시스템 사례로 보는 편이 유용합니다.

01

검색과 정렬은 다른 일

Retrieval은 넓고 빠르게, Ranking은 좁고 정밀하게 일합니다. 첫 단계에서 놓친 정답은 뒤 모델이 되살릴 수 없습니다.

02

점수와 정책은 다른 일

모델은 관련성이나 행동 가능성을 예측하고, 제품 규칙은 권한·안전·가중치·임계값을 적용합니다.

03

최종 결과만 보면 늦다

후보 출처, 제거 이유, 단계별 점수, 실제 LLM Context를 남겨야 실패한 단계를 찾을 수 있습니다.

CHAPTER 04 · RANKING & DIVERSITY

정답 하나의 점수와
결과 집합의 품질

Reranker는 후보 하나씩 정밀 평가하고, 다양성 단계는 상위 결과 전체가 같은 내용으로 도배되지 않게 조정합니다.

후보별 다중 신호

하나의 모호한 관련성 점수 대신 관찰 가능한 요소를 분리하면 정책 변경과 장애 분석이 쉬워집니다.

질문–문서 의미 관련성0.86
정확한 용어 일치0.72
최신성·출처 품질0.61
중복·낮은 신뢰 감점−0.18

Candidate Isolation

후보 A의 점수가 같은 배치의 B 때문에 바뀌지 않게 먼저 독립 평가합니다. 캐시·재현·A/B 분석이 쉬워집니다.

doc Adoc Bdoc C
→
score(q,A)score(q,B)score(q,C)
그다음 후보끼리 비교합니다독립 점수 상위만 그대로 자르면 같은 문서의 인접 청크가 결과를 독점할 수 있습니다. MMR이나 DPP처럼 “점수는 높지만 이미 선택된 것과 덜 겹치는 후보”를 선택합니다.

작게 시작하는 다양성 규칙

  • 같은 원문 문서에서 최대 2개 청크
  • 동일 URL·작성자·도메인 비율 제한
  • 선택된 청크와 유사도가 높으면 감점
  • 서로 다른 근거 유형을 최소 1개씩 포함

확률 보정이 필요한 때

순서만 만들 때는 단조 변환이 랭킹을 바꾸지 않을 수 있습니다. 그러나 소스가 다른 점수를 섞거나 “0.8 이상만 사용” 같은 임계값을 적용하면 calibration이 중요해집니다.

  • 소스 간 점수 비교
  • 자동 답변/검색 결과만 표시 분기
  • 안전 조치 임계값

공식 근거: Phoenix Ranking의 후보 격리와 다중 행동 출력은 Phoenix README ↗, 다양성 재정렬 구현은 VMRanker ↗를 참고했습니다.
