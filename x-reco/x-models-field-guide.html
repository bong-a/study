CHAPTER 00 · WHAT COUNTS AS A MODEL?

이름이 있다고 모두
AI 모델은 아니다

추천 시스템 문서에서는 학습된 신경망, 그래프 알고리즘, 여러 모델을 호출하는 서비스까지 모두 “시스템” 이름으로 등장합니다. 먼저 종류를 구분해야 역할을 오해하지 않습니다.

학습 모델

데이터로 파라미터를 배움

Transformer·MLP처럼 학습을 거친 가중치가 새로운 입력의 점수나 벡터를 계산합니다.

Phoenix · BDSM · adult-content
수학 알고리즘

정해진 계산 규칙을 실행

그래프나 집합을 수학적으로 계산하지만, 일반적인 신경망 학습 모델은 아닙니다.

SimClusters · VMRanker · UserCredV2
모델 시스템

모델을 호출하고 결과를 묶음

하나의 가중치 파일보다 데이터 로딩·모델 호출·라벨 저장을 포함하는 제품 시스템입니다.

Grox · Agatha · Media Model Proxy
비모델

저장·규칙·실행을 담당

게시물을 캐시하거나 규칙을 평가하고 여러 단계를 연결합니다. AI가 없어도 동작합니다.

Thunder · Botmaker · Home Mixer

“X에서 만들었다”의 좁은 뜻

Phoenix와 BDSM처럼 X의 문제에 맞춰 설계된 고유 모델·시스템을 뜻합니다. 코드명도 X 내부 시스템의 이름입니다.

“X가 구현한다”의 넓은 뜻

CLIP·PageRank·DPP의 기본 아이디어는 X가 발명한 것이 아닙니다. 이 저장소에는 X의 구현과 운영 연결 코드가 공개되어 있습니다.

따라서 이 문서의 “X 모델 전체”는 공식 README가 For You와 Visibility에 연결된 것으로 열거한 공개 모델·알고리즘 시스템 전체를 뜻합니다. X 내부의 비공개 모델까지 모두 안다는 뜻은 아닙니다.

CHAPTER 02 · RECOMMENDATION

무엇을 찾고
어떤 순서로 세울까?

Phoenix라는 한 이름 안에 후보 수집 모델과 랭킹 모델이 따로 있습니다. SimClusters가 다른 방식으로 후보를 보태고, VMRanker가 마지막 순서의 반복감을 줄입니다.

01
학습 모델 · Transformer

Phoenix Retrieval

수백만 게시물에서 사용자와 가까운 비팔로우 후보를 벡터 검색으로 찾는 1단계 모델.

phoenix/ONLINE · OON SOURCE
INPUT최근 행동 이력 + 프로필 문맥

반응한 게시물의 순서, 국가·언어 같은 거친 사용자 특성

→
PROCESS두 개의 타워가 같은 벡터 공간으로

User Tower는 사용자 벡터, Candidate Tower는 게시물 벡터를 만듭니다.

→
OUTPUT내적이 큰 Top-K 게시물

사용자 벡터와 가까운 후보 ID 목록

왜 Two-Tower인가?

게시물 벡터를 미리 계산해 인덱스에 넣어 두면, 요청 때 사용자 벡터와 빠르게 비교할 수 있습니다.

무엇을 학습하나?

좋아한 게시물은 가깝게, 무관한 게시물은 멀게 놓는 대조 학습을 사용합니다. 공식 설명은 favorite를 양성 신호로 듭니다.

헷갈리지 말 것

최종 순위를 정하지 않습니다. 넓은 바다에서 랭킹 모델이 볼 작은 후보 풀을 만드는 역할입니다.

실제 구현에서 한 단계 더 보기
  • 사용자 타워는 행동 이력을 Transformer로 인코딩하며 production 설정에는 학습된 사용자 ID 임베딩이 없습니다.
  • 후보는 멀티모달 임베딩에서 만든 6단계 Semantic ID와 해시된 작성자 ID를 사용합니다.
  • 체크포인트를 저장할 때 후보 타워가 코퍼스 전체를 계산해 검색 인덱스를 체크포인트에 함께 넣습니다.
  • 서빙은 정규화된 사용자 벡터와 게시물 벡터의 내적으로 Top-K를 찾습니다.

02
학습 모델 · Multi-task Transformer

Phoenix Ranking

각 후보에 대해 좋아요·답글·체류·신고 등 여러 행동 가능성을 한꺼번에 예측하는 2단계 모델.

phoenix/ONLINE · SCORING
INPUT사용자 + 행동 이력 + 후보 묶음

게시물·작성자·행동·Semantic ID·시간·표면·게시물 나이 등

→
PROCESS후보 격리 마스크가 있는 Transformer

후보는 사용자와 이력은 보지만 다른 후보는 보지 못합니다.

→
OUTPUT후보 × 행동별 확률

여러 행동 logit과 dwell 관련 연속값

왜 여러 확률인가?

좋아요 하나만 최적화하지 않고 클릭·체류·팔로우·부정 반응을 각각 예측한 뒤 정책 가중치로 합칠 수 있습니다.

후보 격리란?

A의 점수가 같은 배치에 B가 들어왔는지에 따라 바뀌지 않게 후보끼리 attention을 막는 장치입니다.

모델 출력 ≠ 최종 점수

RankingScorer가 확률에 가중치를 곱해 최종 점수를 만듭니다. 가중합은 모델이 아닌 제품 규칙입니다.

공식 production 구조의 숫자 보기
  • 공개 README의 production 랭킹 설정: 임베딩 차원 2560, Transformer 8층, GQA 20 query / 4 KV heads.
  • 이력 길이 1022, 한 번에 후보 64개를 다루는 설정이 공개되어 있습니다.
  • 학습 코드는 JAX, 온라인 서빙 레이어는 Rust이며 합성 데이터용 nano 설정도 제공합니다.
  • 후보별 다중 라벨 분류와 dwell time 같은 연속 신호 회귀 head를 함께 둡니다.

03
그래프·클러스터 알고리즘

SimClusters

“누가 무엇에 함께 반응했는가”에서 관심사 공동체를 만들고, 공동체와 가까운 게시물을 찾습니다.

simclusters/OON SOURCE
INPUT사용자·게시물 참여 그래프

계정들이 어떤 계정·게시물에 반응했는지

→
PROCESS공동 반응을 관심사 클러스터로

사용자와 게시물에 여러 클러스터 가중치를 부여

→
OUTPUT클러스터가 가까운 후보

팔로우 밖에서 발견한 관련 게시물

장점

텍스트를 직접 이해하지 않아도 사람들의 집단 행동에서 주제와 취향을 발견할 수 있습니다.

하나의 클러스터만?

사용자와 게시물은 여러 관심사에 동시에 속할 수 있습니다. “개발 0.7, 축구 0.2” 같은 희소 표현으로 생각하면 쉽습니다.

신경망인가?

이 가이드에서는 학습된 신경망이 아니라 그래프 기반 표현·후보 수집 알고리즘으로 분류합니다.

04
수학적 재정렬 · DPP

VMRanker

점수가 높은 글만 연달아 놓을 때 생기는 “비슷한 글 반복”을 줄이는 다양성 재정렬 서비스.

vm-ranker/RERANKING
INPUT후보 점수 + 임베딩

각 게시물의 품질 점수와 서로의 벡터 유사도

→
PROCESSDeterminantal Point Process

품질과 집합의 다양성을 함께 크게 만드는 순서를 계산

→
OUTPUT조금 더 다양한 순서

점수를 약간 양보하고 이웃 게시물의 유사성을 낮춤

쉬운 비유

시험 점수만 보고 팀을 뽑지 않고, 능력은 높으면서 역할이 겹치지 않는 조합을 고르는 것과 같습니다.

새 점수를 예측하나?

아닙니다. 이미 계산된 점수와 임베딩을 받아 순서를 다시 정합니다.

딥러닝 모델?

DPP는 확률·선형대수 기반의 일반 수학 도구입니다. X가 이 문제에 맞춰 서비스로 구현했습니다.

CHAPTER 03 · CONTENT & MEDIA

게시물과 이미지가
무엇을 담았는가?

이 계열은 피드 요청이 올 때마다 무거운 분석을 다시 하지 않습니다. 게시물이 발행될 때 텍스트·이미지·영상을 분석하고 점수·라벨을 저장해 둡니다.

05
LLM 분류 시스템 · 부분 공개

Grox

Grok 계열 LLM 호출을 작업 흐름으로 묶어 새 게시물의 스팸·성인물·폭력물 분류와 멀티모달 표현을 만듭니다.

grox/OFF REQUEST PATH
INPUT게시물 텍스트·이미지·영상

게시물 발행 이벤트와 분석할 콘텐츠

→
PROCESSFlow + LLM 호출 + 후처리

작업 계획, 데이터 로더, Grok sampler, 분류별 flow

→
OUTPUT분류 결과와 숫자 표현

스팸·안전 카테고리 및 텍스트·이미지 임베딩

하나의 모델인가?

아니라 보는 편이 정확합니다. LLM을 여러 분류 작업에 연결하는 실행·오케스트레이션 시스템입니다.

공개된 흐름

저장소에는 reply spam, UPA, PTOS, multimodal embedding 같은 flow와 공통 실행 엔진이 보입니다.

가장 큰 빈칸

구체적인 Jinja 프롬프트는 악용 방지를 이유로 비공개입니다. 따라서 분류 기준을 완전히 재현할 수는 없습니다.

adult-content

미디어 임베딩을 받아 성인 콘텐츠일 확률을 내고, 운영에서 해석하기 쉬운 확률로 보정합니다.

adult-content/MEDIA SAFETY

→
PROCESSBatchNorm → GELU Dense → Sigmoid

왜 작은 모델인가?

이미지의 복잡한 특징은 앞선 임베딩 모델이 추출했으므로, 이 모델은 그 벡터를 분류하는 얕은 신경망이면 됩니다.

보정은 무엇인가?

0.8이라는 점수가 실제로 약 80%의 양성 비율을 뜻하도록 검증 데이터로 점수 눈금을 다시 맞춥니다.

점수 = 조치?

아닙니다. 점수나 라벨은 Visibility 규칙의 입력 중 하나이며 사용자 설정·국가·관계가 최종 결과를 바꿀 수 있습니다.

→
PROCESSFrozen CLIP + Dense 50 + Sigmoid

왜 계정도 보나?

같은 시각 특징이라도 계정이 과거에 올린 콘텐츠와 주변 반응이 추가 문맥을 줄 수 있기 때문입니다.

누락 플래그란?

계정 점수가 없다는 사실도 별도 입력으로 넣어, 기본값 숫자와 실제 낮은 점수를 구분합니다.

파일 이름의 experimental

공개 파일은 model_experimental.py입니다. production 전체와 동일하다고 확대 해석하지 않습니다.

10
학습 모델 · 행동 시퀀스 Transformer

BDSM

계정이 시간에 따라 수행한 행동 순서를 읽어 봇·스팸·조작 같은 비정상 행동 패턴을 찾습니다.

bdsm/STREAMING · ACCOUNT
INPUT최근 512개 행동 시퀀스

행동 타입, 시간, 표면, 체류, 기기·클라이언트, 대상 해시

→
PROCESS양방향 Transformer + 8 task heads

시간 간격을 반영하는 RoPE와 별도 MLP head

→
OUTPUT8가지 계정 행동 점수

head별 확률과 임계값을 넘은 탐지 결과

FollowBotLikeBotEngagementAmplifierReplySpamBotTweetSpamBotRTBotMultiActionBotLegitimateUser

왜 순서가 중요한가?

같은 행동 횟수라도 몇 초 간격의 기계적 폭주와 며칠에 걸친 자연스러운 활동은 의미가 다릅니다.

어떻게 학습하나?

backbone은 마스킹 속성 예측과 대조 학습으로 사전학습하고, 8개 task head는 저장된 CLS 표현으로 별도 학습합니다.

무엇이 비공개인가?

실제 조치 임계값은 9.99 sentinel로 가려져 있어 공개 코드 그대로는 탐지가 발동하지 않습니다.

구현 파이프라인 보기
  • Kafka 행동 이벤트 → Rust accumulator → sequence prefetcher → JAX GPU scorer → result sink 순서입니다.
  • 256개 행동 타입, 임베딩 폭 1024, 시퀀스 길이 512가 공개 설정으로 명시됩니다.
  • backbone 가중치와 task head는 안전한 NPZ 및 SHA-256 manifest 형태로 제공됩니다.
  • 결과 sink가 head별 threshold와 cooldown을 읽어 challenge·suspend 같은 단계적 조치를 연결하지만 실제 운영 threshold는 비공개입니다.

그래프 알고리즘 · PageRank

UserCredV2

팔로우와 참여 연결망을 따라 신뢰 질량을 퍼뜨리고, 계정마다 0~100 범위의 점수를 만듭니다.

user-cred-v2/BATCH · GRAPH
INPUT팔로우·참여 그래프

계정을 노드로, 관계와 참여를 edge로 표현

→
PROCESSPageRank 질량 전파

신뢰받는 노드와 연결된 계정에 반복적으로 mass 전달

→
OUTPUT계정별 mass와 0~100 score

로그 변환 후 범위를 잘라 저장

왜 그래프인가?

계정 자체의 프로필보다 누가 팔로우하고 상호작용하는지를 보면 관계망 속 평판을 표현할 수 있습니다.

공개 점수식

165.2 + 7.07 × ln(mass)를 계산하고 0~100으로 제한합니다. mass가 0 이하면 0입니다.

AI 모델인가?

PageRank는 학습 데이터로 신경망 가중치를 맞추는 모델이 아닙니다. 그래프 위에서 반복 계산하는 알고리즘입니다.
